# 问答记录与恢复

首次提问前建立记录，恢复时先读已有记录。沿用项目约定，无约定时使用目标项目的 `docs/interviews/<主题>.md`；用户指定路径优先。一个访谈使用一个固定结构 Markdown 文件，主题相同的续谈沿用原记录，新独立主题使用独立文件。记录与需求正文分开，不放进技能安装目录。

## 保存与事实边界

- 每轮提出问题时先保存本轮问题、推荐及理由、示例和依赖；收到用户回复后，先保存实际回复及归纳，再重算 frontier。未回复处明确写“未回复”，不填推荐答案。
- Q001 等问题编号稳定且不复用。用户一条回复涉及多个问题时，各问题引用同一轮答复来源；问题拆分使用新编号并链接原问题。
- 用户回复保留原意和必要原文，与 Agent 归纳分开；敏感凭据不落盘，使用脱敏标记。确认依据引用实际轮次、消息标识（如可用）或可辨识原话，不虚构时间与标识。
- 改口时追加答复历史，标明哪条被替代及原因；当前归纳引用最新明确决定。相互矛盾但尚未澄清的答复保留为未决，不自动选择。
- “已回答”只表示收到答复。仍有未决项时不能视为结论闭合；用户未答、推荐、推断和沉默都不构成确认。延期或排除必须有用户明确决定。
- 保存失败时如实说明，保留聊天中的待保存内容，先解决记录持久化问题再推进后续轮次；不宣称已保存或以改写目标文档替代记录。

## 固定结构

按以下字段维护，未发生事项填写“无”或“未回复”，不编造信息。长回复可以用独立段落及代码块。

```markdown
# <主题>访谈记录

- 目标项目：
- 目标文档：已有路径或计划路径
- 当前阶段：访谈中 / 汇总待确认 / 统一更新中 / 文档待确认 / 已完成
- 当前轮次与恢复位置：
- 本次范围与排除项：

## 问题

### Q001 — <标题>
- 状态：待回答 / 已回答 / 已解决 / 已延期 / 已排除
- 前提与依赖：
- 问题与选项：
- Agent 推荐及理由：
- 具体例子：
- 待更新位置：文件与章节；未知时写待定位

#### 用户回复与答复历史
- 第 N 轮：用户原话或保留原意的回复；注明来源及替代关系

#### 当前归纳
- 已明确结论及答复依据：
- 未决项及其影响：
- 延期或排除依据：

## 最终汇总
- 汇总版本：
- 已解决问题与最终决定：
- 延期、排除及剩余未决项：
- 待更新文档及内容：
- 用户确认依据：未确认时明确标记

## 文档更新与审阅
- 已更新 / 未更新文件及原因：
- 文档版本与问题编号映射：
- 当前版本的用户确认依据：
```

## 收尾与恢复

1. 核对当前范围的必要问题与辅助工作；未解决前提继续提问，用户明确延期或排除的事项保留其影响及范围决定。
2. 在记录中形成最终汇总并向用户展示。用户确认理解一致后记录对应汇总版本及依据，进入统一更新；已有同一内容的明确确认可复用。
3. 统一更新按 [需求文档与结束交付](requirements-delivery.md) 执行。当前归纳映射到实际修改位置，原答复历史继续保留。
4. 暂停、阻塞或提前退出保留当前阶段、未答问题、证据指针与下一步。恢复时读取记录并核对目标文件实际内容，从未决问题或剩余更新继续，不重问已确认且依据未变的问题。
5. 用户改变已确认决定、研究结论使原依据失效，或文档审阅发现新的业务问题时，追加问答并将受影响汇总标记为需重新确认。重新访谈期间保留现有目标文档；新结论确认后统一修订，并审阅受影响版本。排版和错别字修正沿用原交付规则。

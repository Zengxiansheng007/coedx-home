# 报告先核对后提问

进入 P1/P2、出现多组报告、附件缺失或版本冲突时先走本入口，再沿用
[完整 P0 契约](p0-evidence-contract.md)。日期相近、最新报告、用户选择均不是通过证据。

1. 读取同一任务问答 MD 的实际决定、完整批准 P0 范围和当前候选。
   目标版本有明确来源且依据未变时直接沿用；不能为了报告选择重复问版本。
2. 在授权范围内先读所有候选报告及必要附件，逐项核对象、模块、语义/数据/
   系统版本、功能验证范围和结果。不要要求用户先选一轮才读取附件。不能访问、
   不能解析或版本不符时保留原来源、缺口及受影响用例；不要假称读过或通过。
3. 用中文展示“对象—版本—范围—报告声称结果—证据核对结果—缺口”，技术标识
   只用于定位。可查事实自行核查，只对剩余歧义和用户范围选择提问。
   问题先用 `advance_record(qa_path, 'record_context', {'display': 完整正文,
   'basis': 来源定位})` 保存并回读，再全文发在正常对话中。
   沿用唯一问答的稳定 Q 编号，检查旧问题最大编号后分配；保留问题、可自定义
   选项、推荐、理由/代价、具体例子与受影响范围。假设例子明确标注。
4. 等待实际回答。用 `record_note` 先保存实际原话、source_ref、归纳、问题编号、
   选定 tested_version/selected_paths 及来源适用范围；`read_notes` 从同一 MD
   回读，不另存答案 JSON。已有记录直接续用，不创建第二份问答。
   选择只决定报告适用性，不更新用例规则，不增设业务需求文档审批。
   “不知道”保持未知并问处置；明确延期保留影响；暂定规则仍须明确预期和产品
   核对条件，走既有三路业务规则入口。任何暂定/延期都不能补足实际 P0 证据。
5. 依据真实选择重新核对完整批准范围；不只核对所选报告显示的子集。缺附件、
   版本冲突、重复报告仍待核对，说明对应 P1/P2 受阻；无关已明确内容保留。
   完整结果仍调用 `p0_evidence.check_extension`，手动启动、暂定继续、覆盖复核、
   规则汇总、完整用例评审及执行边界维持原契约。

## 公开读取适配

`scripts/report_reconciliation.py` 提供 `reconcile_reports(catalog, baseline,
report_paths, request, authorized_paths=..., mode='production', selected_paths=None)`。
传入当前已确认目标的 request.tested_version；未明确时不猜最新版本。
selected_paths 仅来自上述唯一 MD 的有效实际选择，不能由日期推断。

report_paths 每个文件是既有 P0 envelope 的单份 JSON。authorized_paths 是已授权
读取的准确本地文件列表，包含报告和所需附件；解析真实路径后检查，报告中出现
路径不自动授予访问权限。evidence 项可加 path（相对报告目录或绝对路径），读取
实际 UTF-8 内容替换缓存 content，保留原 sha256 让既有 checker 校验。
required_attachments 列出额外必要文本附件；JSON 附件若声明 tested_version
须与报告一致。二进制截图/其它原生格式由 Agent 用相应只读工具查看并按旧契约
归一化，不能声称这个文本适配器已看过图像，也不能用文件存在代替检查结果。

返回 read_sources 的实际读取摘要、gaps、中文 chat、reports 和既有 check。
needs_selection 仅提示尚有适用性歧义；实际问题仍须 Agent 根据已读内容编写，
缺文件不能凭空变成用户版本选择题。程序不会解释任意附件的业务意义或认证
报告生产者，Agent 必须比对每项原始证据与真实检查对象。

模拟用 `mode='simulation'` 且来源及回复标明模拟；通过也只代表模拟入口。
此适配不执行测试、不合并，不改变批准范围或把问答当成完整通过证据。

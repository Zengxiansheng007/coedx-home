# 旧任务恢复与批次范围收尾

恢复或具体稿评审后读取本参考，同时沿用 [原问答与来源恢复](qa-record-contract.md)。先读原唯一问答、实际稿和来源；保持原路径、已确认答案、部分答复、未决与历史。旧记录缺新字段不等于需要重问。旧的自然语言 MD 不转换成另一个业务总账：按原章节继续记录，无法直接调用事件适配器时执行以下同一规则并如实说明。上游 TPD 问答只引用准确路径/章节和适用来源，不合并进 TCA 问答。

## 收尾条件与永久依据

仅汇总确认不能收尾。部分具体通过只允许收尾可独立成立且已保存回读的范围；不得清空未通过整批。先实际读取同版候选与评审材料，核对具体版本、范围、真实评审原话及来源。正文、规则、范围或依赖存在实质差异时仅退回受影响评审。保存或回读失败不进入清理。

清理前在原唯一问答的永久区保存：来源与覆盖复核、具体稿路径/版本、原评审原话及范围、明确延期/排除依据、完整产品问题与影响、已用 B/Q 最大编号及非数字身份、实际保存位置。永久依据不能只引用即将删去的临时行；永久事件绝不删除。未知仍是未知，不因具体稿通过变成产品已确认。

事件适配器的公开入口为 `close_record_scope(qa_path, candidate_path, case_ids, branch_ids, *, scope_bindings=None, source_catalog=None)`。先通过既有 review/review_feedback 记录具体稿评审，实际保存候选，再调用此入口。它重新读取真实候选并要求与事件回放完整一致；当前覆盖的拟收尾行必须有明确 case_ids，全在本次具体通过范围内，状态已处置，延期行还须 impact。

对每个拟收尾用例，用当前来源重新还原其完整含义，包括同版审批的用例。提供引用实际所需的 source_catalog；外部 technical_handoff.source_ref 从实际稿目录定位和回读。来源缺失、绑定失效或声明的摘要不符时，保留受影响的临时范围。独立内联用例仍可按其实际完整内容核对。

局部反馈后，未变用例可以保留原 final_review。复用旧版评审还须从**同一 QA 的真实 review/review_feedback 事件**重建原评审快照，比较完整用例、实际引用的数据、还原的完整操作/整例依赖、来源注册、公共适用与排除/频次、活动显示决定及其可见表达。全部相同且当前依赖可还原才复用，不重签、不修改旧版本标签。仅输入候选里的 approved、调用者声明 unchanged 或自报摘要不能建立证明。部分副本及 P0 整步引用仍传实际读取的完整 source_catalog；历史来源只取原评审事件中的输入。复用旧版评审时，声明 technical_handoff.source_ref 的外部资料还须具有历史 sha256 并实际回读匹配。

首次记录已归属具体用例的覆盖分支时，直接保存其准确 case_ids；共享分支列出全部归属用例。资料、整体业务与规划等尚无具体稿的分支可继续无绑定保留，不因阶段结束而收尾。旧分支缺 case_ids 时先实际核对永久观察、完整稿及来源，再显式补绑定；不要用 record_coverage 仅为补字段而清空有效汇总，也不要由 topic/标题自动推导范围。例如：

```python
import hashlib
import json
from qa_record import read_record, close_record_scope

state = read_record(qa_path)
branch = next(b for b in state['coverage']['branches'] if b['id'] == 'B101')
binding = {
    'branch_id': branch['id'],
    'branch_digest': hashlib.sha256(json.dumps(branch, ensure_ascii=False, sort_keys=True).encode('utf-8')).hexdigest(),
    'case_ids': ['EXAMPLE-1'],  # 根据实际来源和完整用例核定，不能按标题猜。
    'provenance': '实际来源#章节及归属核对依据',
}
close_record_scope(qa_path, candidate_path, ['EXAMPLE-1'], ['B101'],
                   scope_bindings=[binding], source_catalog=current_complete_catalog)
```

摘要现场计算自永久 coverage 的原分支。未知身份、过期原值、冲突归属、重复或越过本次批准范围的绑定均拒绝；已有 case_ids 或已永久补绑定的归属不能无声覆盖。缺省不补 scope，缺绑定仍拒绝。绑定随现有 scope_closure 永久依据保存；原 coverage、候选、summary/summary_confirmation 及原答复逐字保持，不另建答案权威或补业务审批。

`record_coverage` 在同一 MD 尾部生成有界临时投影，以 tca-temporary:start/end 标识；其原观察已永久存于事件。收尾先使用原 record_context 保存 scope_closure 元数据并回读，再原子移除选中行，最后回读原事件及剩余行。永久保存绑定核对时实际读取的问答和候选字节；清理使用只追加本次永久依据后的问答及相同候选。若发现其他写入，停止并重新读取依据和范围。该入口校验结构与文件一致性；语义判断和真实用户身份仍由各自来源支持。

对于没有事件格式的旧问答，按原临时区边界和行身份进行同样顺序。无边界、多边界或永久依据误放临时区时先核实位置，不能按标题整段删。原稿、永久问答、待产品事项、其他范围和历史证据始终保留。不另造临时表归档。

## 中断与局部变更

中断先读实际文件。若永久依据已保存且临时行仍在，重新核对当前来源、问题和覆盖。原条件仍成立时，用相同准确范围和 scope_bindings 重试原关闭入口，只补清理。行已移除时复用已有依据，不重复保存评审或递增版本。只在读取到实际删除且回读一致后报告完成，无法读取时报告待核。

清理后新业务变化只重开受影响条件及实际依赖，新 B/Q 超过永久最大编号且引用旧决定；未变确认、历史原话与其他临时行保持。未清理问题的补答仍沿用原 Q。适配器拒绝改写已收尾 Q 或复用已收尾 B 表达新含义；新 record_coverage 保留原永久分支并另增新 B，未变已收尾行不重新进入临时投影。跨阶段也不冒用旧编号。恢复、反馈和新批次遵守同一规则。

完成仅表示当前编写范围已具体评审并保存及有界收尾。后续阶段按已有效授权推荐或承接，不扩大成合并、执行、发布或产品验收。

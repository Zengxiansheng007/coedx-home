# 批量请求输入

将浏览器复制的 cURL 存入本机 UTF-8 文本，传给 Writer 的 --requests 参数。每条命令独占一行，可用 Bash 反斜线或 cmd 的 ^ 续行。将可公开的中文标题写在命令前一行。支持两列 Markdown 表格，第一列写标题，第二列写单行完整 cURL。Markdown 链接或单独 URL 仅当同批已有唯一对应的完整请求时才能作为别名。请求内容有差异的同地址链接需要补贴 cURL。

支持 -X、-H、-b、-d、--data-raw、--location 等静态浏览器请求参数。正文按 Content-Type 的 charset 编码，缺省使用 UTF-8。将授权 Cookie 放入本地账号文件。业务头、一般参数、正文及标题会进入交付材料，请先替换其中的个人信息和私密业务值。文件上传、二进制、动态签名及未支持的参数需补充静态文本请求或澄清重放约定。

预检汇总位于 summary.md，其中列出已解析标题和每个待补项。修改本地原输入的受影响行，以新输出目录运行。通过后，targets.md 记录目标编号与原标题。

Bash 的 ANSI-C 引号（如 `$'第一行\r\n第二行'`）支持换行、回车、制表符、引号及反斜线转义。其他转义会触发预检提示。Referer 等业务头中的地址也要移除凭据查询项。

v0.3 可直接接收聊天中带 Markdown 链接、HTML 空格实体和续行符的 Windows cmd 粘贴文本。保留每条请求的原标题。对于登录目标，抓包内的 -b 或 Cookie 请求头应能匹配账号文件中的一行；原样轮使用该行。原样轮保留原 URL 查询值。整理时移除查询串中的 ctoken，保留其他参数和 Cookie 中的同名字段。原生导入依赖 JMeter 5.6.3。

## 确认身份与账号行

有 Cookie 的抓包默认按需登录处理，无 Cookie 的抓包默认按访客处理。Cookie 仅用于追踪、目标的身份要求不明确、或用户希望验证登录状态时，先向用户确认每个目标的分类。使用可重复的 `--guest-target T02` 明确要求访客请求，或 `--login-target T01` 明确指定需登录请求。需登录目标应提供含完整会话的原始抓包，使原样试跑可以核对实际账号。

本地 UTF-8 文件首行为 `cookie`，每个后续物理行是一份完整且唯一的 Cookie。使用 `--pilot-account 2` 选第二条数据行。打开计划时读取计划旁的 `.private/accounts.path`，其中一行是本机账号文件的绝对路径。换账号或移动计划时更新本地引用。交付 JMX、原生报告和分轮 JTL，账号数据另行保管。确认响应要求各账号查询令牌后，在独立复验目录传入 `--ctoken-target T01 --ctokens 本机文件`。该文件首行为 `ctoken`，行序与账号一致。

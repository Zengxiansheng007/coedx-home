# 交接与提示词

先按入口步骤核对当前问题、材料身份及实际适用的 Skill 规则。以下是咨询检查方向，具体条件以本次读取的正文及触发参考为准；不缓存完整流程或固定协议版本。读取规则只形成建议，不运行下游脚本、API、编译器、证据检查器或业务流程。

## P0 转 ui-test

读取实际 test-case-authoring 的评审/执行/合并规则和 ui-test 的交接输入、流程与完成条件参考。核对完整用例正文、公共准备/数据引用、评审对象与版本、功能验证范围、环境角色、禁止操作与授权缺口；摘要不能替代完整用例。保留已评审身份，说明下一步由用户另行调用 ui-test 准备正式脚本和完整匹配验证。评审不是执行；验证结果、正式合并和用户合并指令分别判断，不能从其中一项推导其余已完成。

ui-test 内部生成、探索、验证、证据与执行规则由其自身入口负责；咨询仅说明与当前交接有关的条件。若正式跨 Skill 报告映射或生产链在实际规则中仍待联合验证，原样保留限制，不能凭材料可读或模拟成功声称链路已完成。

## 返回 P1/P2 编写

读取实际 test-case-authoring 的 P1/P2 入口和 P0 证据参考，再读当前完整批准范围、实际报告和必要附件。说明身份、模块、语义/数据/待测版本及功能检查证据是否对应；展示范围、准备数据复用和部分合并不能缩小完整批准轮。旧版、缺附件、局部或未运行结果保留其原身份，不扩展为当前全量通过。

依据本次规则说明用户手动启动、适用的临时产品规则继续决定、缺失核心 P0 的审查与用户处置等独立前提。咨询可以解释已知缺口和受影响步骤，正式逐项核验与编写由用户另行调用 test-case-authoring；本入口不替其运行核验流程，也不宣称业务入门条件已获正式批准。缺失或变更 P0 按实际规则建议返回受影响的澄清、评审和下游验证，而不是重做全部有效成果。

## 可复制请求

只有需要切换或跨对话时给提示词，按当前问题裁剪。包括：目标 Skill 与请求动作；任务/模块/完整相关范围；必要资料位置及版本；可追溯的已明确状态；未决、缺证及下一步。凭据只用引用，敏感位置以可安全分享的引用替代。未知或无法读取的信息直接标注，不补写完成状态或虚构路径。

提示词让下一入口核对材料后接续，保留当前授权边界。没有业务执行授权时请求准备和列缺口，不把“建议执行”写成允许提交。跨对话时保留尚待确认的业务条件与历史证据身份，避免下一位把局部评审、旧报告或模拟结论当作全量完成。交付可复制文本即结束，不创建新对话、不发送消息、不调用目标 Skill。

## 普通答疑和内部排障

一般概念直接简短回答，无需索取整套材料或附交接长文。ui-test 的探索、定位器、脚本或运行故障请求，说明本入口止于交接咨询，指向 ui-test 及其实际规则指定的对应入口；用户需要时提供包含症状、错误材料、准确范围和未知原因的请求。保留根因未知，不在本入口开展其内部排障或改稿。

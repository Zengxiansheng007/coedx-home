# 局部质量建议

用户提出测试点或用例的具体质量疑问时读取。沿入口定位实际材料与规则；咨询不执行原 Skill 的编写、问答登记、更新或评审流程。

## 共同依据与差异

先回读相关 PRD 条目、有效答复和当前稿，逐个子规则比较业务含义、适用对象、条件及结果。测试点组织问题按实际 test-point-discovery 的编写/评审参考核对；涉及用户差异再读其权益参考。指出哪些共同内容有来源、哪些真实差异应保留，引用具体位置。相同组件不是共用表达的必要前提，同名字段也不是规则相同的充分依据；没有共同依据时仅询问影响本问题的含义或规则，不猜阈值、空值处理或结果。

有共同规则时建议提到字段/规则层单写并注明适用对象，差异分支保留实际变化。合看共用内容与差异，应能恢复每个对象的全部适用检查。保留已纳入的独立场景及其触发条件，例如切换后的输入残留，不能因目标配置相同便删除。

表达合并与实际验证次数分别判断。规则相同但实现未知时仍可共用表达；必要验证由下游结合现场控件和规则证据确定。本次咨询不据共用写法宣布只执行一次。

## 组织与粒度

沿用已决定的组织主线，指出当前局部重复或粒度问题及具体修改方向。测试点保留必要条件、检查对象和已知结果；普通相邻数据可建议改为有依据的规则表达，真实不同处理与特殊边界仍保留。完整操作步骤、全部数据组合留给用例阶段；规则不明的部分保持未知。目录调整只作建议，不代替用户已有组织决定。

## 用例预期

用例问题按实际 test-case-authoring 的内容/输入契约核对；P1/P2专属规则仅在该阶段适用。将“正常”“成功”等含糊预期与来源比较，建议补齐已知的业务效果和可观察验证点，并保留角色、初始状态、对象、数据及步骤限定。录制行为是观察，材料规则和AI建议分别标明；缺少预期就指出缺口，不把观察或推测升级为已确认规则。提示文案、时限和后续送达等没有依据时不填默认。

## 输出边界与结束

回答对应问题，给出实际依据、具体建议及必要的少量局部示例。示例标为“局部表达示意”，说明采用的已知前提；新增假设单独标为假设，不写成真实业务决定。发现覆盖风险时指出风险、依据与待决定范围，保持建议身份，不自动加入测试范围。

本问题的建议、必要未知和下一步清楚即结束；不能据局部检查宣布整份内容完整或正式评审通过，不生成全量稿、不修改现有文件。正式测试点修改/评审回 test-point-discovery，正式用例修改/评审回 test-case-authoring，由用户自行调用。

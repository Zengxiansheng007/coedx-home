# 基础导航与证据身份

在已读本次实际适用 Skill 规则后使用此导航；这是选路原则，不是被咨询 Skill 的完整工作流副本。具体入口要求、支持格式和门槛以本次实际规则为准。未安装与不支持须分别说明，不把推荐当作可用性证明。

| 当前材料与问题 | 建议入口与接续点 |
| --- | --- |
| 有PRD，需要理解业务、模块范围和测试点 | test-point-discovery，核对输入后从尚未完成的整体理解/规划或模块澄清继续 |
| 已有有效规划、问答或测试点 | test-point-discovery，读取当前展示版本、范围及实际答复，接续澄清/编写/具体评审或反馈，不要求重新规划 |
| 有完整手写P0或Playwright录制，需变为完整用例 | test-case-authoring，对应手写/录制入口；录制只读，不执行；可选PRD按实际规则处理 |
| 已有测试点，准备编写用例但无完整P0或录制 | 建议test-case-authoring并指出其实际输入缺口；测试点不是已完成P0，不假定能直接转换。让用户选择补齐对应P0输入或提供已有完整用例 |
| 已有P0候选、已答问题或反馈 | test-case-authoring，从当前批次澄清、规则汇总确认或完整具体稿最终评审的实际缺口接续 |
| 当前P0已评审，询问执行或后续P1/P2 | 保留当前版本评审身份。分别核对适用规则中的执行证据与手动启动前提；报告不对应则先补证据或处理受影响版本，不宣称已具备下一阶段全部条件 |

阶段结论至少绑定当前任务范围、材料版本与可追溯来源。仅在有实际依据时使用“已确认/已评审/已合并/已执行”；它们相互独立。用户说“通过了”而不能确定对象和版本时，只追问本判断需要的对象/版本。局部报告不扩大成完整范围通过。

普通问题如“评审和执行有什么区别”直接解释区别；不为回答一般概念索要整套任务材料。问“现在该继续哪里”才读取当前任务证据。缺失规则的具体门槛保留未知，同时给出已能确定的方向。

需要流程偏差诊断、局部质量咨询、跨Skill/跨对话衔接时，后续能力应各自有按问题触发的参考；基础导航本身不代做其详细诊断或下游业务流程。

# 流程偏离诊断

用户询问未提问即转产品、确认被跳过或其他流程异常时读取。诊断只形成建议，使用入口的只读边界。

## 对照后归因

1. 固定所问任务、阶段、受影响条目、发生时采用的规则版本及记录范围。读取实际 Skill 正文、本分支参考与用户指出的记录，引用路径及章节/轮次。当前安装版不自动等于历史执行版；版本对应不明时，只能作条件判断，说明缺少什么。不要复制一份旧规则作为以后咨询的依据。
2. 将观察与规则逐项对照：实际做了什么、规则要求什么、两者在哪里不同，以及影响哪个预期、处置或推进条件。文件中没记载不能单独证明对话从未提问；核对完整相关问答或明确记录边界。资料已有明确规则时，未问本身未必是遗漏。
3. 按证据区分以下判断，可有多个局部结论，不必硬选一个总标签：

| 判断 | 所需依据 | 建议 |
| --- | --- | --- |
| 执行遗漏 | 适用规则明确要求某动作，完整相关记录显示未做或提前推进 | 返回受影响步骤，沿用其余有效工作 |
| 规则冲突 | 同一适用版本、范围和条件有不能同时满足的要求 | 并列引用冲突及影响，建议原流程先澄清适用约束；不擅自裁决 |
| 能力缺口 | 目标和适用范围明确，读取相应规则/接口后可定位尚不支持的能力 | 说明具体缺口、可复用部分与可选替代建议；不虚构已有能力 |
| 证据不足 | 规则版本、记录完整性、任务身份或关键动作不可核实 | 说明已知与未知，只补问能改变当前判断的资料；仍回答已有依据部分 |

“模型忘记”“上下文太长”等原因没有直接证据时仅为推测。用户不满意不是 Skill 缺陷证据；规则没有某一句话也不足以证明能力缺口。

## 未问即转入【待产品确认】

先按实际所用编写 Skill 判断，不能把 test-point-discovery 的状态术语强套给 test-case-authoring。前者核对实际澄清参考中的资料直接解决、未问、漏答、部分回答、不知道、明确暂留与依赖规则；后者读取实际批次澄清参考核对问题、处置、摘要确认及完整用例评审。

若适用规则要求明确暂留决定，而完整记录表明业务未知尚未提问、用户也未作暂留决定，却已转产品：指出具体条目与规则差异，判断执行遗漏；影响是未知被当作已处置，依赖该处置的出稿或推进缺乏依据。建议用户让原 Skill 返回这部分问题，核对来源后实际澄清，再按真实答复决定继续位置。建议区分“只是不知道”和“明确后续问产品”，不代用户选择处置。

如果规则允许资料直接明确、用户已有有效暂留决定，或仅有不完整截图/旧版本不明，则说明没有证明偏离或尚不能判定。不要为了认定错误要求重问已明确规则。

## 恢复建议与结束

保留无关内容、原问答历史、有效规则决定、排除及具体评审；只标出受影响范围及直接依赖建议重核的位置。不要建议全量推倒重来，也不要把纠正标签当作补足真实问答。用户需要后续操作时提供可复制给原 Skill 的局部请求，携带准确材料位置、已知状态、仍缺证据与继续步骤；仅供用户另行调用。

说明依据、差异或限制、影响、建议恢复位置后结束。不改写问答、测试点、用例、Skill 或业务状态，不启动原 Skill、不发送交接、不宣称修复已完成。

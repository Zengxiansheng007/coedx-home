# #189 节选范围内取得 P0 输入

使用编写中入口 `source_preparation.py --candidate ... --case ... --output-dir ...` 与合入前入口 `scoped_review.py --catalog ... --request ... --output-dir ...` 分别交付以下三组。完整候选含 194 例，输入评估沿用 #188。合入前入口用 `incremental-v1` 创建只含选中用例的范围副本，范围外父稿由版本与内容摘要验证。

| 待评清单 | 编写中稿件 | 合入前稿件 |
| --- | --- | --- |
| 056 | 文末可复制 001 的输入一块 | 文末可复制 001 的输入一块 |
| 055、056 | 两例均指向同一块附录输入 | 两例均指向同一块附录输入 |
| 001、055、056 | 两例均指向 001 正文输入，附录数 0 | 两例均指向 001 正文输入，附录数 0 |

每次从 Markdown 实际子节点提取 JSON 并解析，与最初 001 对应调用的完整数据逐项核对。六份均恰有一块完整 JSON。每次另读 `agent.json` 与 `candidate.json`，核对人工稿的版本、实际待评清单和 Agent 索引，六组均相同。

合成回归覆盖同一 P0 的两次调用、同一步内的同名输入框，以及来源父稿缺失或实际内容摘要过期。两个不同调用分别提供可复制块，父稿待核对时展示目标自身输入。附录本身没有可编辑用例或输入身份。

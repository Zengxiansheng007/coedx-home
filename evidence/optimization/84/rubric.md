# #84 独立语义验收

评审者读取实际源码版本、普通输入、Root 每轮实际发送的答复、actor 输出及文件。actor 不读取本文件。允许合理问法与顺序，以实际含义及产物判定，逐项定位通过、失败或未验证。

1. 实际从当前工作树入口读取模拟资料，沿已有规划接续。已知字段规则及取消新建的业务效果可直接整理为候选，未反复询问其已明确结果。额外排除范围沿用。
2. 对保存和送审尚未决定且影响范围的终点分别提问，问题按现行问答机制提供可自定义选项、假设例子、推荐理由与代价。示例及推荐仍是建议，实际选择来自 Root 后续发送的模拟用户回答。
3. Root 先只选择保存后，保存候选止于生成草稿并能关联同一任务及必要内容。送审尚未回答时保持未答和必要追问，不能把保存的选择推广到送审，也不能自动转入产品区。
4. Root 随后单独选择送审终点后，候选包含审核端收到同一任务，使用任务编号核对提交的名称、内容及已知待审核状态。保存与送审本轮的止步位置可从产物恢复。
5. 取消候选表达关闭表单、舍弃未保存内容、没有新任务及再次新建为空这一已知业务效果，限定新建情境。按钮存在、可点击或配置组合均不足以代替操作结果。保持字段条件及状态限制，不新增已有任务取消的规则。
6. 审核通过/驳回后的结束、发布、渠道送达均未被自行加入本轮确定检查。资料知道存在后续环节不等于用户已纳入其终点。假设示例不成为天津或其他项目的事实。
7. 逐轮实际输入、回复、模拟来源、文件版本和剩余状态可恢复。候选保持待评审，不虚构具体评审、准确基线或真实业务认可。现行入口若已通过某项，如实记录，不为取得 RED 改造测试含义。

主持方只回应 actor 当轮实际问过的内容。先实际选择保存止于草稿产生，暂留送审答案以观察部分回答，再实际选择送审止于审核端收到同一任务，最后请求展示本轮候选。根据真实问法调整措辞，不能预填一整场通过会话。

# #81 独立语义验收

评审者读取当前 fixture、Root 实际发送的每轮回答、actor 实际输出和文件。actor 不读取本文件。按通过/失败/未验证定位真实轮次和文件，允许合理问法及顺序，不按题数、固定措辞或关键词计分。

1. 首轮实际读取入口与 input，沿模拟范围工作。已明确传渠道不反复问。前提明确的独立问题同轮组织，是否传日期未答时其接收细则仍是未问的依赖问题。
2. 每个业务/范围/处置问题均有可自定义选项、具体假设例子、推荐理由和代价，正常对话呈现。推荐不充当答案。
3. Root 跳过的实际问题保留未答并继续必要追问。不能把漏答、尚未问的依赖或部分答复整体迁为产品事项。
4. 对传值、回显、实际生效、对象与条件分别核对。Root 只答日期框显示时，仅该部分明确，查询是否生效和边界继续追问。不会把一个行为的答案推广到其余。
5. Root 仅答不知道时，actor 实际询问如何处置。Root 明确暂留后才新增唯一【待产品确认】，保留真实决定与影响。相同模块不存在独立【待确认】或【AI建议】类别。范围建议以普通问答承接。
6. Root 明确解答仅形成对应候选规则，未伪造具体测试点评审、准确基线、真实产品认可或用户答复。尚未收到继续/编写决定时保持澄清阶段。
7. 逐轮记录实际问题、示例/推荐、答复与来源、适用对象和剩余状态。未发送轮次标未验证，未预填整个通过会话。历史输出未重写。

主持方按实际问题选择自然语言回复，只发送当轮实际回答。至少经历漏答/部分回答、仅不知道、明确暂留、明确解答四种回复，必要时多轮。每次推进前先核对 actor 上轮确实问过什么。若某分支还未提出，保持未问身份，不能伪称已问。

# 第1轮展示 v0.1

本地模拟开发验证。当前为 M1 规则澄清，尚无具体测试点评审或准确基线。

沿用 PRD v0.1 P1 的已确认接续前提，先做 M1 标签维护，按新建表单、保存、取消组织。名称按两类共用字段编排，用途只适用工作标签。排除批量导入、权限、删除及完整用例，M2 等后续实际继续决定。

P2 中明确的名称必填、中英文各计1、最多12字、超限拒绝并保留输入，以及保存后按同一 ID 核对列表和详情、取消不新增记录，可先保留为待编写内容。以下三个问题彼此独立，可分轮答复，也可自行给出其它规则。

1. 同类重复名称和跨类同名分别允许吗？例如已有工作标签“项目”，再建工作“项目”和个人“项目”应各自成功还是拒绝？可选同类拒绝且跨类允许、两种都允许、两种都拒绝，或分别自定义。PRD 未定，我建议先核实这两个范围。核实前重复相关预期等待，其余明确内容可继续整理。

2. 特殊符号与 emoji 如何计数？例如“甲!😀”中的“!”和“😀”各计多少？可选均按可见字符各计1、采用已提供的明确技术口径，或自定义计数规则与示例，也可明确暂留后问产品。我建议先核实适用口径再写这两类12字边界。代价是相关特殊边界暂不能形成确定预期，中英文边界仍可整理。

3. 工作标签的用途为空时如何处理？例如名称合法但用途留空，可选拒绝保存并提示、允许保存为空、保存时填入指定默认值，或自定义，也可明确暂留后问产品。我建议先核实业务规则。等待期间工作用途的空值分支未定，个人标签无用途字段沿用 P2。

本轮等待这三个问题的实际答复。答复只形成规则澄清结论，具体测试点后续仍需评审。

# R-Q1 当前购买模块澄清（模拟开发验证）

已核读R-P1实际模拟确认。普通100、有效VIP80、无其他费用优惠、本人/他人订单和预约拒绝/可用在资料中明确，本轮不重复询问。四类条件分别为客户角色、普通/VIP权益、有效/到期状态、本人/他人关系；不把VIP当高权限。

以下是同轮独立未知，不要求现在替产品编答案；已有继续决定允许先写有效状态新单，不因提问新增长文批准门。各题可给产品依据、自定义或明确继续待产品。

1. VIP生效依据是什么？例如刚获得VIP资格但页面仍显示普通身份，此时新单按100还是80取决于何种业务生效依据？A给出明确生效事件及依据，B继续待产品。推荐B，当前没有规则，不能以页面刷新或资格受理推定生效。影响VIP价/预约资格及身份变化；如A再按实际事件追问必要时点，不先要求时区答案。
2. 到期瞬间如何判定？例如单在到期前看到80、确认新单时恰逢到期，按什么时点和包含关系判断？A给出判定事件/时区/包含边界，B继续待产品，或自定义。推荐B，不能从会员标签或自然日假定判定规则。影响到期附近价格及预约，未答不套80或100。
3. 已有未支付订单遇到权益变化怎样处理？例如原80元订单尚未支付，会员已到期，应保持原额、重新计价还是其他？A保留原额，B按明确重新计价规则，C继续待产品，或自定义。推荐C，旧单不能直接借用单件新单规则；影响订单金额和结算承接，场景仍必需覆盖。

风险范围沿R-P1，不新增安全性能；现有明确拒绝检查属于业务规则，不因不扩展安全而排除。回答仅作为业务澄清及继续范围依据，具体测试点尚未展示评审，准确MD尚不存在。

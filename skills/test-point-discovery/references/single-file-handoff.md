# 单文件交接与局部未决

收到交接请求或用户选择先交已明确部分时读取。交接对象是经具体测试点评审更新的一份最新准确 MD 及其中资料引用；首次尚无准确文档时，先走具体评审，不把规划同意、业务答复或推荐当评审。复用[评审与推进](review-and-progress.md)及必要的[反馈重审](feedback-review.md)，不另建导入器或权威清单。

## 分析依赖，再建议范围

实际读取准确文件的版本、当前范围、来源条目和实际决定。分别核对每个候选分支：场景是否纳入、哪些规则已明、哪些仍未答或冲突、关联对象和上下游传递、前置条件与结果依据。没有待确认标签也必须回查依赖，不能把批准等必要条件写成充分条件。缺失引用明确指出其影响，保留已有内容，暂停依赖该来源的交接结论。

例如财务复核条件未知会影响付款资格，即便付款按钮分支没贴问题标签；付款成功回写同一申请的对应检查不自动解决资格。昨日金额依赖成功记录和时间口径；独立图例显隐若只改展示、不改数据，可建议先交接，但须解释依据。这只是分析示例，实际结论取自本次资料。

简述可交接分支及理由、建议保留分支及具体未决影响，按[分轮问答](module-clarification.md)给先交明确部分、等待或自选范围的自然语言选项、假设例子、推荐理由与代价，由用户实际决定。沉默、推荐、场景纳入或已有评审都不替代交接决定。不默认全模块阻塞，也不默认无标签即无依赖。用户可拒绝推荐或交接带问题内容供下游澄清，记录其限定用途，保留未知，不把决定范围变成确定预期。

## 承接实际答复

等待时保持尚未交接，保留问题、全部分支和原评审；拒绝推荐时按实际答复的范围和理由执行，没有替代决定就保持未交接。部分交接引用原准确文件的实际分支，未交部分保留，不当删除或永久排除。已有有效决定直接复用，避免重复索批；版本、对象或范围歧义只问必要澄清。

交接决定变化时更新同一路径的说明区和文档版本。已决范围、决定原文和历史集中在说明区，建议/范围的剩余未答保留过程状态并继续处理，明确暂留的产品事项保留在对应模块/流程顶部【待产品确认】。仅状态及说明变化不改变具体检查及其评审适用版本，业务规则或具体检查变化先走反馈重审。开发模拟由主持方逐轮发送实际回答，执行者记录展示版本、模拟来源、适用范围和未决，实际使用依然由真实用户决定。

## 同文说明与回读

在准确 MD 的“资料与Agent交接说明”集中维护以下信息，沿用已有效历史，不让用户再填 JSON 或维护第二清单：

- 当前版本、覆盖范围、本轮更新/评审范围和正文适用的展示版本；准确文件、历史过程材料和局部副本身份清楚。
- 资料可读引用、标题/条目/版本及其对应测试点分支；问答限定含义保留，不能仅列文件名。
- 依[编写约定](writing-review.md)保存默认共用约定、共用适用范围和真实差异、跨模块提取的实际决定，以及已知/未知实现依据与下游现场核实边界，接收者可据此恢复各对象检查并确定必要验证。
- 实际决定原文或可定位引用、来源身份和作用范围；分别记录场景纳入与规则明确。模拟开发确认明示模拟，不作真实业务确认。
- 明确暂留的【待产品确认】及其真实决定依据，其他未答的当前状态、下一步、受影响分支与上下游依赖。已纳入而未明仍须澄清，范围决定不能替代规则。
- 用户决定的本次交接分支、保留分支、理由与用途；推荐与实际选择分开；等待/拒绝未自动交接，未交接不是删除。
- 下游责任与进入条件：完整用例留给下游；下游自行核对整轮 P0 范围、实际报告与必要证据，处理缺口及未决，再由用户手动启动 P1/P2。拿到 MD 不证明 P0 通过，不授权执行、合并或自动启动。

回读保存的唯一准确 MD，核对正文/问题区/映射/决定/范围一致，未交分支和有效确认无丢失。接收 Agent 应只凭该 MD 与其引用恢复检查、来源、实际决定和未决影响；必要答案仍只在聊天时，先写入同文说明或可读引用再交接。引用须承载真实资料或答复，不链接隐藏预期、rubric或验收答案来代替自足内容。

本交付是 Agent 阅读文档的边界。现有下游 helper 使用其结构化契约，未验证通用 MD 直接输入；不调用或修改 test-case-authoring/ui-test，不宣称程序接入成功。本阶段不生成完整用例、不执行业务。实际文件或客户端未验证项按事实列出。

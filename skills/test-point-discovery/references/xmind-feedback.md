# XMind 回传进入同一评审

新调用或指定阶段先按[八阶段入口判定](stage-entry.md)核对资料、版本和前提；充分历史资料的接续建议等待实际同意。当前流程普通答复沿原阶段与同一问答MD承接，通过入口判定后使用本参考。

用户回传编辑后的原生 XMind 时读取。先实际读取[反馈与影响重审](feedback-review.md)，沿用聊天和MD的实际含义分流；业务变化再走[具体评审与同文件更新](review-and-progress.md)的候选、影响核对、具体评审和确认后更新流程。

用户提供历史人工XMind作为组织参考时，先核对其来源项目和用途，只借鉴表达方式。历史地区的限制、失焦时机、笔误或其他规则不移植为当前预期。读取成功只说明可读；当前业务依据仍按[输入判定](module-clarification.md)核对，疑点实际提问，具体内容仍需评审。

## 八阶段承接

XMind读取成功后沿用聊天/MD相同的阶段7反馈处理。新业务缺口回原问答MD阶段4，经5原始来源和依赖复核、6集中修订、7具体重审；部分回答保留现稿及准确版本。回传文件的编辑或格式成功均不代替具体评审。保存回读准确MD与永久依据并完成适用收尾后，才按已定顺序进入下一模块4，转换时简述成果与下一任务。

## 读取与支持范围

保留原始待评审MD、对应导入/保存的原生原件和回传文件，不覆盖任一输入。记录原范围/版本、当前准确MD路径/版本、用户反馈原文及来源。执行只读入口：

```text
python -X utf8 -B <本Skill目录>/scripts/read_xmind.py <回传.xmind完整路径>
```

先看status。`read_for_agent_review`仅表示格式可读：输出来源hash/字节数和按序topic标题、层级路径、原生ID。Agent实际读这些内容并比较原稿、当前准确MD及回传。原生ID可辅助核实同一保存链中的文字/移动，不能当业务身份或确认依据。来源范围与版本不能靠文件名猜测，缺少原稿或可靠对应先询问。原稿说明区的旧状态不回写覆盖当前准确版本。

`pending_verification`表示格式或附加内容需要核实，保留原件并指出原因，请用户提供可核对的受影响内容或支持格式，暂停依赖不可靠内容的修改。没有成功主题树时不得按空文档处理删除。

支持本地有界ZIP中一个content.json、一个sheet、rootTopic及有序children.attached文本树；允许兼容content.xml同时存在但不读其内容。读取上限16MiB原生文件/单content.json，200条归档条目、64MiB展开大小、65层/50000主题。XML-only、多sheet、自由主题、关系线、笔记、标记、图片等未支持语义保持待核实。样式及主题元数据不承担测试点语义。只按实际验证记录客户端版本和范围，不承诺任意历史或未来格式。helper不提取归档、不输出写入计划、不判定业务规则、不修改准确MD。

## 进入既有反馈流程

取得可靠主题树后先按反馈参考分流技术事实与业务变化。对业务变化逐分支识别文字、层级/移位、增加与缺失，完整核查真实依赖，聚焦展示原来→候选、依据、修改规则与适用范围、受影响差异/联动及必要上下文。层级变化也核业务含义，不能只把树拍平成文字。省略的未改检查及其他模块保留；范围内消失而删除意图不明、同名/拆分/移动后无法可靠对应时，沿用反馈参考的具体询问，未答先保留。未知业务改动按局部机制回源澄清，只暂停受影响预期，不因来自XMind就推定已解决；实际明确暂留的产品问题继续定位。

业务候选进入与聊天/MD相同的具体评审；未评审、拒绝或仅业务答疑时准确文件与版本不动。通过后只把实际展示且通过的具体修改合入原准确MD路径，同文说明区追加回传身份、来源版本、范围、来源到规则路径、展示版本、实际评审及未决；保留同分支省略的未改检查、其他模块及期间聊天/MD有效决定。实际回读正文、层级、版本及说明区。XMind是反馈输入，不成为第二份权威，不自动修改下游。

## 客户端验证

实际将本Skill生成的范围MD导入目标客户端并核对中文/条件/问题区/说明区/必要层级，保留原生原件。先另存新测试副本，再编辑文字和层级、本地保存回传；记录实际版本、输入/原件/回传hash、操作和观察来源。用上面的真实入口读取回传，走候选→具体评审→同MD更新。可复用已有真实导入证据，明确其原始草稿身份及后续准确版绑定。合成ZIP只证明解析；开发模拟答复标明身份，不替代真实客户端往返或真实业务确认。

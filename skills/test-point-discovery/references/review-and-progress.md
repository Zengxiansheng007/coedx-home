# 具体评审、准确文件与逐模块推进

当前模块的具体测试点已实际展示、收到反馈时读取。由 Agent 直接读取和修改 Markdown；不要求用户填写 JSON，不新增批准表或通用存储系统。

## 识别本轮评审

核对实际展示的待评审文件/版本、当前模块与完整分支、反馈原文和来源。仅当用户明确认可这些具体检查时，才认定该范围通过；支持自然语言和自定义意见，不以关键词判断。规划确认、业务答疑、生成完成、推荐与未答保持各自属性。对象或版本不明时只澄清该歧义；已有明确评审不重复索批。

首次无准确基线就明确写尚无；待评审草稿版本不是准确文档版本。开发模拟每轮标明模拟来源、展示版本、回答原文、适用范围与未决；限定技术行为通过不等于真实用户或产品确认。实际使用等待真实用户决定。

## 未通过与修订

明确不通过或要求改动时，保留当前模块待评审，准确 MD 及其版本保持不动。按意见修订当前候选，保存原展示材料与答复，递增草稿版；说明业务变化并呈现受影响分支的完整新内容，重新交具体评审。若意见引入未知规则，先澄清或保留问题，不自行选择。只批准部分时仅纳入明确通过范围，其余保持待评审并记录；不能以总体“可以”消除明确保留项。

已有准确文档的聊天/MD修改、歧义删除或跨分支影响时，读取[反馈与影响重审](feedback-review.md)完成范围核对与完整分支候选，再回本文件处理具体评审与更新；当前草稿的修订也沿用该影响核对。

## 通过后更新同一文件

1. 读取现有准确 MD（若有），固定其路径和版本。本轮确认只适用于实际展示内容；在获授权位置首次创建时采用清楚的文件名，以后更新同一路径。未获写入授权时展示内容并说明尚未落盘，不声称文件已更新。
2. 将已通过的当前模块分支纳入该文件。准确文件使用一个一级标题，模块及其顶部问题沿用待评审树形格式；合并到同一个“资料与Agent交接说明”。保留未展示的其他模块全文、原来源对应、有效评审结论和未决影响。省略不是删除；不要用局部草稿覆盖整份准确文档。
3. 递增准确文档版本，例如首次v1、下一次v2；在说明区记录本次展示版本、评审原文/位置及来源、已通过与保留范围、来源条目到分支、场景纳入与规则已明确的区别。历史决定按原身份与范围保留，新决定说明替代范围；未答产品问题继续在相应模块顶部及说明区定位。纳入测试不等于预期已知。
4. 实际回读保存文件，核对本轮内容、其他模块与说明区一致，报告准确路径、版本、更新范围与未决。待评审副本和过程材料保留其历史身份，不能另称为最新准确文档；历史版本取证副本需明确只作历史证据。

## 进入下一模块

当前具体内容通过并更新后，核对已决定的顺序。仍有未决时，沿用用户已明确的继续/保留范围；未决定则简述影响，提供继续明确部分、暂留依赖部分或等待的选择及推荐理由，等待决定。当前未通过就留在当前模块。

在决定范围内回入口澄清、编写、自检、评审下一模块；不重复已确认规划，也不每轮增加新批准门。第二模块未通过期间第一模块准确内容保留；通过后追加到同一文件，而不是新建第二份准确文档。不能因允许继续就清除前模块问题或扩展纳入范围。

尚无交接决定时保持尚未交接；收到交接请求再读[单文件交接](single-file-handoff.md)，按实际依赖建议并承接范围决定。下游完整用例、P0核对和人工启动职责不变；不自动运行下游、修改已有用例或执行业务测试。

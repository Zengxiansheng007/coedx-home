# 规则与计算

新规划先按[规划前业务理解](planning-confirmation.md#规划前业务理解)厘清主要操作与关联，实际询问影响划分的问题，再提出模块表图。整体阶段的明确规则仅记为分析依据，尚不形成测试点稿；已有确认规划的接续沿用其范围与顺序。

金额、条件或公式决定结果时读取。以“规则 → 条件分支 → 结果、边界与优先级”作为建议主线；字段维护只是输入操作时作补充，不机械扩展审批、支付、角色或完整状态目录。说明选择理由、裁剪和混合范围，由用户决定；沿用入口规划表图与具体评审门。

1. 从 PRD 与实际说明识别参与计算的字段、结果、阈值及条件；记录冲突和缺口。逐项核对金额字段含义、币种与单位、允许输入范围/精度、中间和结果精度、阈值比较哪个阶段的值、等于是否包含、舍入模式与时点、运算顺序、优惠叠加/互斥、优先级、封顶或负值处理。资料未涉及的能力不默认存在，必要未知项提问。
2. 同轮问独立前提，依赖问题等真实前置答复。金额单位精度未明时不提出确定“99.99/100”的业务预期，叠加/顺序未明时不算确定会员结果。每题按[分轮问答](module-clarification.md)给具体假设例子、可自定义选项、推荐理由与代价。需要的精度可解释为“分/厘或其他”，由用户实际回答。
3. 按同处理规则读[等价类](method-equivalence-partitioning.md)，按已明确范围与最小可表示单位读[边界值](method-boundary-values.md)，条件共同决定结果读[决策表](method-decision-tables.md)。内部表用于暴露缺口，不让用户维护大型矩阵；无关条件合并须有依据，不把两两组合称作全规则。
4. 答复后按[规则级编写](writing-review.md)表达必要条件、计算规则、真实分支及已知结果。常规邻值用于内部核对精度与包含关系，待评审点保留阈值、单位、精度和越界处理。能区分运算顺序、舍入时点或特殊业务边界的必要例子保留，结果独立手算核对，不机械列出所有相邻值或组合。
5. 按[共用范围与差异](writing-review.md)单写模块内相同计价规则并标明适用功能，各功能的口径、条件、顺序与结果差异分别保留。按[输入判定](module-clarification.md)将明确规则直接形成候选，已纳入但未明结果继续提问，实际获暂留决定后才记产品问题，其他已明确部分能否继续沿用用户决定。额外风险先说明价值、成本与选择，已排除沿用其项目范围。入口自检覆盖字段、单位、精度、阈值、舍入、顺序、叠加的去向，不以组合数量宣称充分。具体点经评审后才更新同一准确 MD。

假设示例：已明确原额满100减10后乘0.9，末尾四舍五入到分，输入100.05元，则(100.05−10)×0.9=81.045，结果81.05。换一种运算顺序或舍入方式不一定同值；规则未确认时此数值只是方法示例，不能移植为项目预期。仅发现测试点，完整数据组合和执行业务留在下游。

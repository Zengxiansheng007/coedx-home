# 错误推测与检查表

来源：[ISTQB CTFL Syllabus v4.0.1](https://istqb.org/wp-content/uploads/2024/11/ISTQB_CTFL_Syllabus_v4.0.1.pdf)，2024-09-15，§4.4.1 Error Guessing、§4.4.3 Checklist-Based Testing（核读2026-11-07）。以下将官方经验技术适配为测试点发现；本 Skill 只提出检查，不执行测试。

## 错误推测（Error Guessing）

官方要点：借助经验预想可能的错误与失败。项目应用：从资料和经验提出候选遗漏。

- 适用：资料已有主线，需要补查易遗漏的输入、结果或衔接；不适用：用推测裁决冲突、证明缺陷或填补确定业务预期。
- 缺失信息：历史问题是否真实发生、涉及哪类对象？当前是否有相关能力？期望如何判定？没有历史证据时标为一般假设，不能编造事故。
- 步骤：找具体薄弱环节→说明风险、测试价值、成本与选择→让用户决定额外范围→对纳入场景实际询问未知规则→根据实际答复形成检查或依明确暂留决定记录产品问题。沿用[输入判定](module-clarification.md)，已知规则直接推导的检查无需逐项重问。
- 假设示例：批量导入可能出现“条数正确但联系人编号错配”。建议核对源目标编号与字段值，说明可发现对象错配及增加逐行核对的成本，由用户选择范围；未采纳不写正文，不能认定已经错配。假设重复提交可能重复创建，但是否允许重提、怎么处理尚未知，先问能力再写预期。
- 误用检查：把经验当需求、把候选当已发生缺陷、默认重试或幂等、用“常见问题”掩盖来源缺失，都须纠正。纳入场景不等于结果规则明确。

## 基于检查表的测试（Checklist-Based Testing）

官方要点：检查表组织测试条件，各项应能独立检查。项目应用：用精简核对表发现遗漏并产出具体点。

- 适用：对已识别对象和功能补漏、回查资料覆盖；不适用：把通用清单当穷尽覆盖证明，或让清单替代业务理解及问答。
- 缺失信息：当前适用对象、用户关注、实际输入/状态/终局、判断结果的规则。不能回答的项转问题，而不是勾选“通过”。
- 步骤：选与本模块有关的少量检查方向→逐项核对资料及当前具体点→说明遗漏、建议与排除→用户决定新增范围→回查每项的条件/结果/未知。规则变化时更新适用条目，避免清单无限膨胀。
- 假设示例：联系人导入核对“受理与完成区分？同一任务？同一联系人？源目标字段？错误行可定位？”。若目标重复编号规则缺失，先实际询问，获明确暂留决定才记产品问题；不会因为清单出现“重试”就要求系统提供重试。已排除项沿用其项目范围。
- 误用检查：写“数据正确”而不可判断、只对总数、把自动格式检查或阶段通过门混入业务检查、机械套全表、把打勾当实际执行或充分覆盖，都不满足本适配。

两方法只帮助发现候选，不能代替具体测试点评审。方法/格式验证不证明业务通过；具体数据组合、完整步骤和实际运行仍由下游决定。

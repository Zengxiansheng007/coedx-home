# 规划绘图与确认

新调用或指定阶段先按[八阶段入口判定](stage-entry.md)核对资料、版本和前提；充分历史资料的接续建议等待实际同意。当前流程普通答复沿原阶段与同一问答MD承接，通过入口判定后使用本参考。

整体业务理解开始时读取本参考，达到下述划分条件后再绘图。直接沿用已实际阅读的 PRD、用户说明、候选模块和关系；续接时重新核对其来源与版本，不要求用户另填 JSON。

## 阶段1～3推进与停点

入口阶段定义沿用[八阶段入口](stage-entry.md)，本节落实首次规划的连续动作。每次过渡先保存并回读同一问答MD中的成果依据、当前阶段和下一动作，再用一句话说明成果与下一任务，随后实际开展下一阶段。没有需要用户决定的事项时当轮继续，无需单独征求“下一步”。

| 当前使用阶段 | 完成核对 | 随即开展的工作或等待 |
| --- | --- | --- |
| 1 接收并核对资料 | 实际读取来源、版本、本轮目标、排除、冲突与缺失，定位唯一问答MD，明确无疑点规则记为依据 | 材料足够则简述已核对成果，进入2分析主要操作。缺失来源时说明影响并等待补充，只暂停依赖内容 |
| 2 澄清整体业务 | 按下节核对主要操作各自起点、变化与上下游，影响划分的必要未知获回答或明确处置 | 足够支持划分则简述业务依据及处置，进入3生成候选表图。必要问题未答、部分答复或仅不知道时承接原问题等待，明确内容继续整理 |
| 3 确认模块划分与梳理顺序 | 当前版本表图已实际生成、读图且一致，并一起展示供确认 | 未答或要求修改时停在3。实际确认后保存对应版本与范围并回读，简述已定边界和首模块任务，进入4实际核源及澄清；无需再问是否开始 |

阶段1发现充分历史资料时仍按入口的接续建议等待决定；本节自动过渡不替代接续同意。已知规则直接保留来源与适用范围，只对会改变边界、组织或顺序的未知关系提问，字段细节留待当前模块。

## 规划前业务理解

逐项核对原始资料中的目标、角色、同一对象及标识、主要操作的起点/结果、分支和环节衔接。已知内容记为依据，操作之间如何复用对象、触发下一环节或影响顺序尚不明时，按[分轮问答](module-clarification.md)实际询问。问题可同轮集中，依赖实际答复才成立的问题留待后续。已明确结果沿用，字段细节留到模块深入，除非它会改变边界。

例如虚构资料只有创建消息的保存、取消、提交审核入口时，先分别核对保存对象、取消是否改变已有对象、送审使用哪个对象及审核接收关系。结果取自资料和真实答复，不能从按钮名推断草稿、删除或状态。操作可同属创建模块，实际拆分依据是职责、对象与业务衔接。

影响划分的关系已有依据或用户明确延期/排除等处置，且未知影响可定位时，才提出模块、顺序和关联简表图。未处置问题继续等待，不先让用户批准依赖未知关系的规划。保留明确处置项的未知属性，方向未知写双方问题注记。无需用户重新审阅长篇已知业务说明。此阶段只维护分析/问答依据，不形成待评审测试点或准确基线。

候选表先列模块ID、边界及排除、组织主线与补充视角、梳理顺序和理由，再列用相同ID定位的关联及来源。七类按实际内容取舍，使用入口所链接的各类参考。信息维护可承载保存/取消等同对象操作，跨模块协作以流程串联，生命周期补状态/事件，规则计算补实际条件结果，看板补指标口径，权益补真实用户差异，异步补受理/过程/最终结果。仅存在角色、按钮或字段名称不足以据此独立拆模块，也无需为了七类齐全增加资料未定义的范围。

## 生成实际图与图片

1. 加载当前可用的 archify Skill 及其类型对应 schema、示例和交付契约。在已授权输出目录创建本轮独立产物目录。默认模块有向关联用 architecture；单父包含才用 tree，不把所有模块规划强制变成流程图。未提供 archify 或无法运行时报告准确失败阶段和缺失产物，保留候选，不伪称绘图完成。
2. 从同一候选表提取模块 ID、名称、范围、顺序、方向、触发、传递内容和未知事项，写实际 archify candidate。模块节点标明候选/确认状态及梳理顺序；范围排除与关系缺口用注记保留。生成的 JSON 只是绘图输入，不是另一份准确测试点或用户维护清单。
3. 已知方向的未知传递内容在对应箭头上写“传递内容未明”，按[输入判定](module-clarification.md)实际提问；有用户明确暂留决定才写“待产品确认”。方向未知时，在图注中列出双方和问题，不编造 from/to。不能用虚线单独表示未知（默认可能表示异步）；未知关系不升级为已确认事实。共同筛选不推定模块互传数据，没有有据关系时明确说明，不为了连通补箭头。
4. 完整 candidate 写好后按 archify 的 `finalize` 实际生成 HTML 并完成自动门；失败依契约修复，保留失败证据。无远程访问授权时关闭其版本联网检查，不增加外部模型、远程品牌资源或依赖安装。
5. 使用其 `visual-check` 获取 PNG 并实际读图核对。PNG 若仅为视口截图须明确标注；如果图未完整呈现，通过 Viewer 的 Export 导出完整 PNG 再查看，不能用截断截图冒充完整图。核对名称、范围/顺序、方向、传递内容、条件、未知关系及可读性。捕获成功只证明文件生成，读图和语义核对另行记录。

## 表图一起供确认

在同一次回复给出最新简表、可打开的 HTML、图片和必要待决摘要。请用户确认或修改本轮范围、组织主线与梳理顺序，允许直接给自定义调整；不要要求批准长篇业务需求。保存实际展示的材料路径和本次答复，不用预填确认替代用户回答。

每次展示标明同一规划版本，并在唯一问答MD保存该版本简表、candidate、HTML与PNG的实际路径、读图结论和等待对象。确认仅绑定实际展示的版本及范围。产物缺失、生成或读图失败时保留候选与失败，准确说明缺少的交付和下一修复动作，保持阶段3待完成，不把表格同意写成表图完成。

收到明确范围/顺序修改后直接更新候选简表及图中的相同内容，保留业务规则未知属性。重新实际生成并读图，再一起提供最新表图确认。未改变关系也要核对是否仍与新范围一致；后置目的端仍可作为关联背景保留，不能悄悄转成全模块检查。方向或业务含义不明的调整先询问，不猜测。

修订递增规划版本，旧展示与答复保留历史身份，当前恢复位置改为等待新版确认。用户未答继续等待，拒绝则请其说明希望调整的范围或安排，并只整理已有依据；均不深入模块4。含糊的“继续”按其原问题核对，尚不能确定是否同意当前表图时实际问清。

只在真实答复明确同意当前表图规划时标为“规划已确认”。局部确认仅适用该部分；若对继续范围存在歧义，保持待确认，不进入依赖它的澄清。推荐、未答、旧图确认不能批准改后的版本；模拟演示答复统一标注“模拟”，与真实用户确认分开保存。

## 确认后的交接

规划确认的实际答复原文、历史及处置更新在[唯一问答 MD](module-clarification.md)，沿用整体业务提问时的同一路径。在规划材料的“资料与Agent交接说明”保存展示版本、来源、该问答 MD 的实际路径与永久章节引用、已决定范围/排除摘要、顺序与下一模块，以及未答关系和规则各自的下一步；不另建规划问答台账。产品事项须引用明确暂留决定，规划同意不处置漏答。没有真实答复则写“尚无真实规划确认”，不得填造时间或来源。

明确：范围确认不代表业务规则明确，也不是具体测试点评审。按确认顺序进入当前模块深入澄清；已纳入跨模块业务保持流程优先分析，衔接检查归入约定的当前模块范围，不在整体阶段独立生成流程测试点。回到入口读取“模块分轮澄清”参考继续，不重复批准已确认规划；具体测试点编写和评审仍属后续能力，不生成正式准确测试点 MD，不启动下游。

开发验证经明确授权使用模拟回答时，逐轮保留展示版本、实际模拟回答、来源、范围和未决状态，只标“模拟规划确认”；允许继续模拟澄清，不能写成真实业务确认。实际使用的真实用户确认门保持不变。

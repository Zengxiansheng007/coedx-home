# 信息维护与操作

资料描述记录维护时读取。以“模块 → 实际支持的操作 → 条件、字段和结果”提出主线；只选已存在操作。不能从CRUD词组推定删除、导入、批量或恢复。状态影响少量操作时作补充视角；结果主要取决于公式时结合规则计算。七类为项目组织，不要求互斥或填满；实际主线和范围由用户确认。新规划仍走入口表图确认，接续则核对已有证据。

1. 读取原始条目和说明，逐操作识别对象、可操作条件、字段及结果，分别记录已知与未知。必填、格式、长度计数口径、唯一性范围/大小写/空白归一、编辑自身是否重复、哪些字段可改、何时可改、失败时记录如何处理，按业务实际问，不一次问无关百科。
2. 按[输入判定](module-clarification.md)先复用资料可核实的事实；明确且无已知疑点的规则直接形成候选。先问前提明确的独立问题；依赖唯一性范围的重复检查、依赖长度口径的边界值等留到答复后。给具体例子、选项、推荐与理由，允许自定义；推荐不是规则。资料与页面冲突、过时线索及未知预期实际询问，未答不自动转产品。
3. 有同处理依据时读[等价类](method-equivalence-partitioning.md)；有明确有序范围时读[边界值](method-boundary-values.md)；多个条件共同限制操作时读[决策表](method-decision-tables.md)。规则未明先提问，不将方法名当成检查。
4. 建议核对列表、详情、选择器和已存在关联对象的实际影响，说明同一对象与传递字段，由用户决定范围；未知历史对象是否更新继续提问。新增风险说明价值、成本与选择，未采纳不进正文；场景纳入不补全预期，已排除沿用其项目范围。
5. 按入口编写与评审：每操作独立写适用的字段、条件、结果和拒绝检查，包括必要重复；修改编号不可变不能省为“同新增”。不得编造查询不存在时的文案、失败回滚或历史同步规则。顶部集中两类问题，资料映射放同文件说明区。按来源逐项自检，没有检查的内容须有具体处置。

假设示例：资料明确编号全库唯一且不可变，可检查新增重复编号拒绝；改名保存后同一编号详情呈现新名称。是否允许已引用记录改名未知时只保留问题，不默认允许或禁止。具体测试点评审前不更新准确 MD；问答完成及选择组织不构成评审。

# 决策表测试 / Decision Table Testing

出处：[ISTQB CTFL v4.0.1](https://istqb.org/wp-content/uploads/2024/11/ISTQB_CTFL_Syllabus_v4.0.1.pdf)，2024-09-15，§4.2.3，第41页；2026-11-07定向核读。以下步骤适配测试点梳理，不规定产品优惠。

适用：多个条件共同决定动作/结果、存在互斥、优先级或规则缺口。不适用：单字段纯范围问题可先分类/边界；缺失业务结果时不能自行填表作为确认规则；不能由方法反推系统具有优惠叠加能力。

缺失信息：问条件定义、取值、约束、不可行组合依据、顺序、冲突优先级与各结果。未知不等于不关心，不可行不等于尚未回答。

应用步骤：列出条件与结果，逐列识别可行规则；未知/矛盾保留产品问题；只依据真实约束排除不可行列、依据结果确实无关合并列；将各需覆盖的规则转为独立可读检查，不强制把内部大表交用户维护。两两组合不等于全部业务规则，精简须说明保留与排除理由。

假设示例：已明确满额先减10，会员再九折，不满额会员仅九折。则满额/会员、满额/非会员、不满额/会员、不满额/非会员分别检查两优惠、仅减免、仅九折、原额。若叠加未定，第一列是问题，不能填成“取最低价”。

误用提醒：不将未知写成无关条件，不无依据删除失败/冲突分支，不将列数或两两覆盖宣称规则完整。不在本阶段穷举全部输入值，完整用例与测试执行由下游负责。

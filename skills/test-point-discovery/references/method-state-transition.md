# 状态转换精简参考

官方名称：State Transition Testing（状态转换测试）。来源：[ISTQB CTFL Syllabus v4.0.1](https://istqb.org/wp-content/uploads/2024/11/ISTQB_CTFL_Syllabus_v4.0.1.pdf)，2024-09-15，§4.2.4，文档页41—42；2026-11-07核读。

官方定义要点：状态图表达状态与有效转换，事件可附守卫条件和动作；状态表还可表示无效转换。官方覆盖标准涉及实际执行；本Skill仅发现测试点，不报告执行覆盖率。

适用：同一对象在不同状态对事件/操作有不同响应。不适用：没有状态差异的纯展示或字段检查；不为套方法虚构状态。必要信息：对象与标识、实际状态、事件、前置条件、后状态/动作及已明确禁止变化；缺失、冲突先问。业务生效时点、时区/包含边界与状态下允许动作是本项目额外核对视角，不能拿官方模型的瞬时转换假定补业务时序。

应用：读取规则和实际答复→整理已知转换/未知问题→按状态与事件写合法及已明确禁止变化、动作和必要条件→核对同一对象/生效时点→交具体测试点评审。时间范围明确后才补时间边界。表格可作分析辅助，不能代替可评审分支。

假设示例：支付确认成功使同一张已领取券变为已使用，已使用券不可再用。核对支付确认生效及再次使用被拒绝；支付受理是否占用、退款是否退券无规则时保留问题，不能补造确定结果。

误用提醒：未定义不等于禁止；不能将未知表格空白当无效转换。已知驳回不等于有重提，失败不等于有重试。覆盖全部状态不等于覆盖全部转换，更不证明真实系统通过；不将本参考的假设当本项目规则。状态表为空或图可打开也不证明覆盖完整。完整序列用例、执行组合与覆盖计算由下游负责。

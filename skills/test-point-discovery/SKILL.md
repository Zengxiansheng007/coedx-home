# 模块测试点梳理

## Safety 与当前能力边界

本版交付 TPD-01A/01B/01C/01D：读取可访问的看板 PRD 和用户说明，形成候选模块规划，实际调用 archify 将表图一起交用户确认，按已确认范围澄清当前模块，编写并自检局部待评审测试点。资料理解和关联判断由执行 Agent 完成，无语义分类脚本、外部模型或业务系统依赖。仅在授权的输出位置写过程材料；否则直接在回复中提供。

本版同时交付 TPD-01E/02/07/08：具体测试点评审后的同一准确 MD 更新、模块推进、聊天/局部MD/受支持XMind反馈的影响重审，以及按实际依赖建议并由用户决定范围的单文件文档交接。局部待评审文件和历史过程材料保持原身份，具体评审通过后才有准确基线。XMind 导入与编辑往返按实际客户端验证，未执行时明确未验证。只梳理测试点，不生成完整用例、不运行真实业务、不宣称 P0 通过或自动启动 P1/P2。

采购、审批等跨模块业务或对象生命周期资料先读取[流程与生命周期](references/workflow-lifecycle.md)，据实际内容选择主线，复用以下规划、澄清、评审及反馈步骤；本分支支持先流程后模块、状态/事件检查与模块新事实回流重审。七类参考接通不代表全部规格验收已完成，按实际证据报告范围。

TPD-03 扩展信息维护与规则计算，TPD-06 扩展数据交换与异步处理，复用相同规划、澄清、编写、自检和具体评审后更新流程。七类是项目组织方案，不是官方测试技术分类；方法参考按需读取，不为每种方法建独立 Skill。

## 使用阶段与入口

新调用、指定阶段、接续建议及普通答复均先按[八阶段定义与入口判定](references/stage-entry.md)处理。未指定阶段的新调用先实际核对当前资料和目标；充分历史依据只触发接续询问，实际同意后才接续。普通回复沿原阶段、原问题和同一问答MD承接。

使用阶段依次为1 接收并核对资料、2 澄清整体业务、3 确认模块划分与梳理顺序、4 深入澄清当前模块、5 问题处置与覆盖复核、6 集中编写待评审测试点、7 人工评审、修改与模块收尾、8 确定交接范围并交接。名称、必要前提与完成条件以上述参考为准，模块按4～7循环。

从阶段1开始的实际推进读取[阶段1～3推进与停点](references/planning-confirmation.md#阶段1～3推进与停点)。阶段1核对足够后当轮开展阶段2，阶段2理解足够后当轮安排阶段3表图；分别简述成果与下一任务。需要实际答复时保存当前停点，规划修改后重新展示一致表图，获当前版本确认后才按已定顺序开展阶段4。

模块阶段4～7及成稿后的局部回流，读取[模块循环与阶段过渡](references/module-clarification.md#模块循环与阶段过渡)。阶段5须回读原始资料并记录覆盖去向，阶段6集中出稿后进入7等待具体评审；阶段7准确MD和永久依据保存回读及适用收尾全部完成后，才开展下一模块阶段4。真实问题与评审处保存停点并等待。

## 内部操作指南

以下操作序号仅用于查找细节，各使用阶段按入口参考的前提调用所需操作。TPD编号及GitHub工单属于开发交付身份。接续、反馈和交接操作都先满足入口判定。

用户功能、数据或价格随角色/会员权益变化时，先读取[角色与用户权益](references/roles-entitlements.md)，贯穿下列分析、组织、自检及反馈步骤。TPD-05增加逐用户适用检查、四类条件区分及权益变化重审，共用范围与真实差异共同恢复各用户完整检查。默认模块→用户类型→功能/规则，替代目录须用户决定。

1. **核对输入。** 实际读取用户指定的 PRD 和文字说明，记录文件/链接、标题或条目位置及可见版本。读取失败时指出具体来源并请用户提供可读内容，保留已读资料但暂停依赖缺失来源的规划。没有 PRD 时只说明本版保留将来无 PRD 入口，请提供可读 PRD；不以一句想法补造业务方案。超出现有参考与输入能力的请求说明实际边界，不以参考接通作为验收证明。
2. **逐条理解。** 看板读取[看板资料分析](references/dashboard-intake.md)；维护记录的实际操作读取[信息维护](references/information-maintenance.md)；条件、金额或公式决定结果时读取[规则计算](references/rule-calculation.md)；跨模块接力或状态变化读取上方流程/生命周期参考，识别对象、参与者、事件、条件、传递与生效，不套图表模板；导入、同步、通知或后台任务读取[数据交换与异步处理](references/async-exchange.md)，澄清、编写和自检时返回该参考核对受理/过程/最终结果及数据对应，实际状态与输入分类只作适用补充。混合资料读取所需参考，按实际内容理解而非关键词分类。识别对象、操作、规则、关联、用户关切和缺口；分组保持分析建议身份。
3. **整体业务澄清。** 先理解目标、角色、对象及主要操作各自的起点、业务变化、分支与环节衔接，按[规划前业务理解](references/planning-confirmation.md#规划前业务理解)核对。保存、取消、提交审核分别分析，其按钮数量不决定模块数量。资料与有效答复明确的部分直接记录依据；影响划分或顺序的未明关系先查资料，仍不明则在对话实际提问并等待回答。沿用[分轮问答](references/module-clarification.md)的问题、选项、例子、推荐及理由，不索要长篇业务说明批准。仅记分析依据与未决，不生成流程或模块测试点稿。
4. **提出候选安排与关联。** 足以支持划分的业务关系已明确，或用户已明确处置其未知影响后，再给范围、排除、顺序、主线理由及关联简表。看板从模块→图表/指标起步，信息维护从模块→实际操作起步，规则计算从规则→条件分支起步；跨模块接力先流程分析后模块，生命周期从对象→状态/事件起步；异步从任务/交换对象→输入受理、过程、最终结果及数据对应起步。七类按实际业务裁剪混合，角色方案沿上方参考。用同一端点名或编号写方向、触发条件、传递内容、来源和未知影响，区分记载、推断及未决。未知方向放注记，未明关系不得被候选命名或箭头变成事实。新增关联与风险先建议，由用户决定范围。
5. **绘图并一起确认。** 按参考中的自检核对候选表和“资料与Agent交接说明”，再读取[规划绘图与确认](references/planning-confirmation.md)。直接调用实际 archify 生成 HTML 和图片并读图，简表与图一起呈现，不新增单独的表格批准轮。按真实反馈同步修订范围、顺序和表图，保存真实答复；推荐、沉默和模拟回答均不算真实确认。
6. **核对规则并澄清当前范围。** 规划未确认时等待。确认后读取[模块分轮澄清](references/module-clarification.md)，按其输入判定先查可核实的事实。已定范围内明确且无已知冲突、过时线索的资料规则及其直接推导先保存编写依据，无需逐项重问；当前模块全部问题明确处置并完成来源覆盖复核后才集中生成待评审稿；影响预期、流程或范围的未知、冲突与过时线索实际向用户提问。额外风险先说明价值、代价与选择，沿用项目内有效排除。集中问前提明确的独立问题，依赖问题等前置答复后继续。通过入口判定的已有规划接续，再核对展示版本、答复及范围，复用有效规划，不重复绘图或批准。纳入跨模块业务时流程优先分析，关键衔接检查归入用户约定的当前模块范围，与该模块一起编写、自检并评审；整体理解阶段仅整理依据，不单独出流程测试点稿。生命周期按实际状态/事件与允许动作处理，按实际证据报告支持及未验证范围。
7. **交付可用结论与未决影响。** 按澄清参考固定唯一问答 MD 的实际路径，跨整体业务、模块、轮次和恢复持续维护临时覆盖区与永久问答；准确测试点 MD 单独承载具体评审通过内容，每轮核对来源、新条件、未问/漏答/部分、事实和依赖，写后实际回读；暂停恢复先读文件。直接在正常对话展示每题全文、可自定义选项、假设例子、推荐理由和代价，用户自由回答；不使用问题卡或平行问答台账。只有明确暂留才进入对应模块/流程顶部唯一类别【待产品确认】，其余未答继续按原状态处理。出稿前按澄清参考的当前模块生成条件回读原始资料、部分答复与相关依赖，主动找回初轮未登记的相关分支，处理后再复核；一批答完、部分已答或frontier为空均不触发出稿。沿用用户已决定的继续范围，仅请求澄清结果时停在此阶段，明确规则答复仍须后续具体测试点评审。
8. **编写并自检待评审测试点。** 请求进入编写、范围已决定且[当前模块生成条件](references/module-clarification.md#当前模块生成条件)已满足时，读取[编写、自检与待评审文件](references/writing-review.md)，应用其中的规则级粒度、共用范围、差异、短节点与名称标记约定。以规则表达常规边界，保留必填、计数、超限、必要条件及特殊边界；简单检查直接写清，独立切换等场景保留触发与结果。模块内相同规则单写并标清适用对象，各图表/功能/用户通过共用范围与差异恢复完整检查。表单按适用字段组织，跨模块共用先建议并等用户决定。逐操作核对必要条件、同一对象的业务结果与本轮终点，明确结果先记编写依据，仅询问尚未明确且影响范围的终点。编写或自检发现新缺口时按该参考的局部往返步骤核源、回问及恢复，只暂停依赖未知的预期，沿用已有明确部分继续分析范围，保留现稿。相关问题明确处置并完成来源及依赖复核后集中出稿；无疑点资料也先完成当前模块复核，不要求等待其他模块。交具体测试点供用户评审，等待其反馈，不进入下一模块或创建准确基线。通过入口判定后，接续已完成规划和澄清时核对已有证据与阶段5覆盖复核，不重复绘图或增加批准轮。

9. **承接具体评审并推进。** 收到当前待评审内容的反馈时，读取[评审、准确文件与模块推进](references/review-and-progress.md)。修改或拒绝仍停留当前模块，聚焦展示修改规则、适用范围、受影响差异/联动及必要上下文重新评审。问题答完、批准延期或规则答复保持其处置身份；当前模块具体稿通过后，才把通过范围合入同一准确 MD 并递增准确版本，实际回读核对正文、版本、未展示内容与未决保留。再按该参考保存并回读永久问答、依据与产品事项，只清理已收尾临时项并回读。当前模块仍有未通过具体内容，或写入/回读未成功时，保留恢复位置并停在当前模块；完成上述步骤后，才按已确认顺序进入下一模块。明确暂留的产品未知继续保留，其他模块与有效决定不受局部展示影响。清理不新增批准门，新信息只重开受影响部分且B/Q编号不复用。

10. **核对聊天与MD修改。** 收到已评审内容的修改、编辑后的局部MD或后续模块新事实带来的跨分支影响时，读取[反馈与影响重审](references/feedback-review.md)，先按实际含义分流技术事实与业务变化。纯技术定位/控件调整按该参考留给下游，按实际对象及证据身份记录即可；业务变化固定当前准确路径/版本、原展示版本/范围和反馈来源，核对实际修改含义与完整依赖，删除歧义先问。新缺口按[成稿与后续模块回流](references/module-clarification.md#成稿与后续模块的新疑问回流)沿用同一问答 MD，只重开受影响范围，保留现稿、有效答复与来源及无关内容和评审状态。部分回答只整理依据，相关问题明确处置并复核后集中修订。展示变化摘要、修改规则与适用范围、受影响差异/联动及必要上下文，省略内容保留。聊天或产品答复仍是依据，具体评审通过后才将通过的业务修改合入同一路径并实际回读。当前模块条件继续适用，通过入口判定的反馈进入本操作，复用未受影响的规划。

11. **接收XMind回传。** 收到原生XMind反馈时，读取[XMind读取与同一评审](references/xmind-feedback.md)，实际运行只读helper并读回传的有序主题和来源身份；固定原范围及现行准确版本，由Agent核对文字、层级和影响，按同一反馈性质分流，仅业务变化进入候选/具体评审/同MD更新。未支持格式、歧义删除及无法对应先核实；不以格式成功代替业务确认。

12. **按决定交接。** 请求交接或先交明确部分时读取[单文件交接](references/single-file-handoff.md)。核对最新准确 MD 及来源，按实际跨分支依赖提出交接与保留建议；分别记录场景纳入和规则明确，等待用户选择。将实际决定、依赖、范围与下游边界更新在同文说明区，回读保真。通过入口判定的交接进入本操作，复用有效规划；没有准确基线则先完成具体评审。文档交接不表示下游程序直导或 P0 已通过。

## Validation 与完成判定

模块八阶段增量使用 `tests/test-point-discovery/stage-97-request.md` 和独立rubric。主持观察后实际发送部分回答、漏答补答、不知道、明确暂留、拒绝/修改、具体通过与后续线索，实走两模块及4→5→6→7局部回流。读取实际问答与稿件，核对阶段5原始来源找回、各次成果过渡、准确版本及保存回读/限定收尾先于下一模块4。聊天、MD与XMind反馈分别按实际入口核查，未执行的语义或客户端验证保持pending。

阶段1～3增量使用 `tests/test-point-discovery/stage-96-request.md` 与独立 rubric，主持在观察后实际发送关系答复、规划修改和当前版本确认。核对资料已知依据、混合组织方案、真实archify及读图、表图同次展示、未答等待、修订重审与确认后实际阶段4工作。父005、006规划段及012资源一致性分项记录；模拟与真实业务确认分别保存，未执行项保持pending。

八阶段入口使用 `tests/test-point-discovery/stage-95-request.md` 与独立 rubric，由主持实际逐轮发送模拟消息，观察默认起点、充分资料接续的等待/同意/拒绝、指定阶段前提和普通回答承接。历史请求继续保留限定证据身份，重新调用历史场景时先适用现行入口判定。静态一致性与实际交互分别报告。

成稿和后续模块新疑问使用 `tests/test-point-discovery/flow-93-request.md` 及独立 rubric，接续同一实际问答 MD、现稿与准确基线。主持分别发送新事实、部分答复、明确处置及具体评审，核对旧稿保持、受影响覆盖复核后的集中修订、拒绝/修改时准确版本不动及通过后的同路径保真更新。未知产品事项、无关内容和有效评审均保持可恢复，静态与实际语义观察分别报告。

# 消息草稿资料 v1

SIMULATION。以下为虚构产品，与天津真实业务无关。

F0 模拟规划接续前提。已选择先处理消息草稿模块的创建表单，三个发送维度均纳入，形成局部待评审测试点。保存以生成一条草稿并在列表显示相同标题为本轮终点，不涉及送审、发送、送达、编辑和删除。公告模块仅供了解关联，尚未决定整理范围。

F1 【发送维度】有站内信、短信、推送三个选项。以下字段都在这张表单中。

F2 【标题】三个维度都必填。站内信、推送上限20字，短信上限10字。汉字、字母、数字、符号和空白各计1字，空字符串视为空值，纯空白也视为空值。超出对应上限或必填未填时不能保存草稿。已知实现事实仅来自本模拟资料，切换维度时标题是同一输入框，但限制按所选维度变化。

F3 【联系人】三个维度都必填，接受11位阿拉伯数字，其他格式不能保存。本模拟资料明确该字段在三个维度下是同一个输入框，校验规则相同。这里的阿拉伯数字指0至9，不涉及真实联系人数据。

F4 【备注】三个维度都可空，上限40字，计数同F2但允许纯空白，超限不能保存。业务规则没有维度差异。没有页面、代码或组件复用证据，三个维度是否使用同一控件尚不清楚。

F5 同样叫【说明】的字段有不同含义。站内信、推送的说明是用户可见补充文本，可空，上限40字。短信的说明是内部备案原因，必填，上限60字。计数同F2，短信纯空白视为空值。超出各自上限或短信必填未填时不能保存。保存草稿后两种说明按各自含义保留，不能因名称相同混用。

F6 保存成功时，草稿列表出现同一条草稿，标题与本次保存一致。以上规则均为本模拟项目当前版本规定，没有新旧版本冲突。

F7 公告模块也有联系人，必填、接受11位0至9数字，其他格式不能保存。下方为公告当前规则片段，提供给本次关联分析。公告现行片段 v1 保留原状，是否把联系人提升为跨模块公共规则尚未决定，消息草稿不依赖公告发布。

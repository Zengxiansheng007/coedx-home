# #86 独立语义评审

仅供 Root/独立评审者，不能交给入口 actor。逐轮输入由 Root 实际发送并落盘，actor 不得自编决定。此处是待验收条件，未记录通过结果。

## 主持场景

先从 fixture 实际生成候选，Root 对实际展示版本具体评审后创建 current.md v1。不得预填当前候选已通过。保存每次展示原稿、Root 输入、版本与路径。

- 聊天将站内信/推送标题上限从20调为30字，短信仍10字。观察共用计数、上限范围、短信真实差异、保存超限依赖是否完整核查。聚焦展示规则变化、适用范围与必要上下文，不重印独立列表及表单无关检查。Root 针对展示版本实际批准后核对同一路径 v2 与回读。
- 基于有身份的已展示版本制作局部 MD，修改正文规则，并省略原有取消节点。Root 提交时不解释该缺失，观察是否问删除或省略。Root 逐轮实际答“只是本轮省略，保留取消”。若修改引入未知，例如正文上限未说明计数口径或超限处理，分别追问并由 Root 实际回答，不能因文件已改就默认全解决。批准前 current.md 版本/内容保持，批准后只更新通过且可独立成立范围。
- 使用明确标合成的支持格式单 sheet native XMind，来源绑定已有展示稿，改变明确范围内标题或保存的规则，带有旧版本说明时核对现行 MD 的期间决定。实际 read_xmind.py 输出保留 hash、层级和解析身份。Root 实际评审后仍更新同一 current.md，保留聊天及 MD 有效决定和列表。

主持人可按实际 actor 输出调整后续反馈，不能提供完整预填整场通过 transcript。避免同轮批准尚未实际展示的内容。

## 六项 AC

1. 三入口均可回读现行准确路径/版本、来源副本/展示版、反馈原文/文件与修改含义。无法对应先问必要问题。接收、答疑不自动更新。
2. 语义完整性按实际业务依赖核查，展示聚焦变化、规则范围、差异/联动和必要上下文。共用规则及真实例外均可恢复，未修改节点全文并非评审必需。
3. 局部省略继续保留。副本内缺失且意图不明实际提问，未答不删除。明确删除可在候选说明对象/剩余范围及影响，无额外删除批准门。
4. 未知规则回局部澄清，仅暂停受影响预期。独立明确部分可继续候选。编辑过文件不关闭未答依赖，只有实际暂留决定才入产品区。
5. 只有实际展示且具体通过范围进入同一准确 MD，版本递增。候选、XMind、历史副本身份清楚。实际读回范围、正文、说明、期间决定和未决，未展示内容保留。
6. 三入口实际运行、具体评审和读回均有对应证据。解析单列为受支持合成输入，客户端往返单列。未跑客户端如实未验证，不能用解析或静态通过充当客户端或真实业务验收。

## 其他检查

只改活跃指令与验收，保留旧输出及固定保真脚本原字节。静态一致性、reader 单元测试、实际入口语义及客户端验证分开报告。

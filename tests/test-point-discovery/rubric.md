# TPD-01A 独立评审标准

先读取 requests.md 指定输入，再审实际输出；核对主要操作和业务关联先有依据，未明关系实际询问早于依赖其答复的规划，整体阶段无测试点稿；允许合理模块合并与不同措辞，不以固定表格字面或测试点数量判定。每项记录通过/失败/未验证、输出定位及理由；发现关键事实遗漏或新增业务结论即失败。

1. A 真实读取 Skill 和两份自然语言输入。范围能追溯首页筛选、两项概览指标、趋势、排行、明细，导出有排除去向；“模块”可为分析分组，但不得冒充 PRD 定义。
2. 保留实际内容：事件条数与用户去重的区别、趋势按天、排行所选日期内前十及降序、点击传递服务标识和日期；不能只列四个标题。用户关切被用于推荐顺序或检查方向，说明用户“先筛选后图表”的要求。
3. 顺序与主线有业务理由，以数据展示与分析作为看板候选主线；卡片、图表与明细及筛选适用范围清楚；不将七类名称列全当作七类实现。
4. 关联可供后续绘图：端点稳定可对上范围表，方向、传递内容、资料/推断/待确认属性清楚；未知是否影响排行、明细渠道不能画成确定联动，不能因共享筛选就捏造图表间双向关系。
5. 保留匿名去重、及时更新的阈值、空图、并列排序、返回保留、排行渠道与会议转述的证据不足；解释各项影响的候选分支，不编造具体阈值、空值表现或裁决口径。PRD 和用户说明均不被当作测试点已获评审。
6. 风险只作为建议，权限/性能不自动纳入本轮；候选规划不成为准确测试点基线，无新增长篇业务需求批准门，也不单独要求批准规划表。下一步为表与图一起确认，而非本轮宣布已经有图。
7. 来源可定位到文件与章节或原文段落，已知条目、用户说明、缺口均有去向；不要求复制整篇 PRD。输出状态为候选、尚未确认；保留后续绘图所需信息与边界。
8. B 只说明无 PRD 流程保留入口、需要可读 PRD 才能开展本版，不编造规划或宣称已完成；C 指出文件不可读并请求可读资料，不补写假内容。

本票仅贡献 TPD-AC-001 资料分析、002 简表及004/007/010/013适用部分。archify 图与确认、澄清问答、测试点编写/评审、准确 MD、XMind 和下游交接均不能由本票证据宣称完成。

## E：TPD-01D 独立评审

写作中新缺口与恢复同时适用 optimization-85-rubric.md。原候选中既有表述仍需核对来源，恢复以实际答复范围为准。按实际问题区及问答身份评审，不将继续候选视为准确MD或交接批准。

按writing-request及其原始来源逐条核对实际产物，不给执行者预填golden结果。文件存在和结构检查不证明业务语义。

- 主样例只能继续渠道参数和已说明的日期接收；计数冲突、日期边界/时区、渠道回显、渠道实际生效、日期实际生效、空数据和刷新分别有具体未决去向。不得由日期显示推定自动筛选或套用渠道显示规则。
- 主样例M2/字段详情后置，权限性能排除，未增加导出/交叉筛选。answer-3的澄清许可不能被追溯说成具体测试点评审通过；本次写点请求仅生成局部待评审材料。
- 独立两图样例按共用适用范围与差异恢复各图完整检查，站点、UTC+8、首尾包含、同月限制、逆序拒绝、空数据、图例恢复及筛选保留相同规则单写。设备按标识去重与告警按记录计数分别正确，避免共用范围掩盖口径差异。旧产物保留历史身份，新行为通过新输出验收。
- S4已纳入告警刷新与周期未知分别保留，依明确暂留决定进模块顶部【待产品确认】。S5的“留待确认”同样保留其实际暂留决定与范围未定，只用同一产品类别，不转成必需导出检查。尚未实际询问或获得暂留决定的建议仍留过程记录。正文没有来源/批准叙述，说明区可从S1—S5追到实际决定与剩余问题。
- 检查项用规则表达常规边界，保留必填、计数、超限、必要条件与特殊业务边界。简单检查可直接写清，相同期望只表达一次，独立切换等场景保留触发与结果。不展开常规相邻数据、完整步骤或全部组合，以前后含义保留和可评审性核对；同文说明区包含来源条目映射、模拟决定属性、范围/版本、自检和未决影响，下游边界清楚。
- 两份产物均待评审，局部缺失不当删除，不创建准确基线、不启动下游；自检有具体覆盖和缺口处置，不按点数判充分。
- 实际XMind将本票MD导入为新文档，核对中文、层级、条件、问题区和说明区，记录版本/hash/观察证据。未执行时只能未验证，解析结果不能替代。编辑回传不在本票范围。

# TPD-01C 独立语义评审标准

评审者先读输入和主持方实际发出的回答，再核对独立执行的逐轮输出；按通过/失败/未验证记录轮次、输出定位及理由。允许不同合理问法和推荐，不按词频、问题数量、表格格式或固定答案字符串判定。未运行不能判通过。

1. 实际先读取入口和两份自然语言资料，承接模拟规划及 M1/M3 范围，没有重开规划批准或进入 M2。首轮能把互不依赖的计数冲突、跳转传参、空数据/更新缺口一起组织，未把 PRD 已明确的渠道是否传递重新当作未知。
2. 每个业务、范围及处置问题提供贴近业务的假设例子、可自定义选项、推荐、理由与主要代价，用正常对话提出。可推荐暂留，实际暂留决定仍等回答，不能把猜测包装成业务答案。不用问题卡或长篇需求批准，不在传日期未定时要求决定日期接收细则。
3. 第1段确实发出后才推进日期接收依赖问题；实际回答“不带平台”保留，不继续逼问如何继承平台。能用第2段的自定义日期答案，保留包含关系/时区缺口，不捏造北京时间、自然日、秒级刷新或计数阈值。
4. PRD 次数/人数矛盾、页面和同事说法分别保留，未获答复仍未决。漏答继续必要提问，部分回答只确认实际对象、条件及行为并追剩余，仅“不知道”先询问处置。用户明确暂留后才进对应模块/流程顶部唯一类别【待产品确认】，顶部保留完整问题和影响，真实决定依据集中在“资料与Agent交接说明”并引用唯一问答。模拟回答保存原文/轮次、来源与范围，不能写成真实产品认可。
5. 风险纳入由用户决定；先说明具体风险、测试价值、增加的成本及选择，第1段排除权限/性能后在本项目范围沿用，不推广成通用禁测。已知范围内规则直接推导的检查无需逐项再问，额外风险未采纳不进正文。“跳转要测”仅表示场景纳入，未知预期须继续实际提问；产品问题绑定明确暂留答复，未问/漏答不自动转入。
6. 未决项影响定位到计数展示、日期接收边界、空数据及刷新检查，询问后续继续范围，不强制全部已知才继续，也不擅自进入 M2。第3段选择后仅整理已选部分可用的澄清结果和未决，不反复请求同一批准。
7. 澄清结果明确哪些来自资料、哪些为实际模拟答复、未答、冲突或 Agent 建议；有来源定位和答复范围。问答结束不等于具体测试点评审，不生成或更新正式准确 MD、不启动下游。
8. 参考通过入口可达，包含 Cucumber 官方来源、章节/版本状态、适用/不适用、缺失信息、步骤、假设例子及误用。官方规则/实例/问题的区分与项目分轮/标签/用户决定契约分开；此项静态核验只是支撑，不能替代前7项实际行为证据。

本票主责 TPD-AC-007—010，贡献006、012、017、020的适用部分；不据此宣布其他 AC 或 #64 整体通过。

## 唯一问答与直接对话复核

逐轮实际检查跨阶段/模块的问答路径保持唯一、正文直接显示完整问题且允许自由回答，未使用问题卡或平行问答台账。准确测试点 MD 身份单列。核对未发问依赖、漏答、部分回答与业务答案未知/处置未定的不同状态，产品暂留必须能定位明确决定。模拟答复由主持实际分别发送，保存先后变化，不能预填通过。

# #88 同版整合验收

仅供主持和独立评审者，入口及接收角色只拿普通请求和实际输入。固定交付runtime的实际commit及物理hash，逐轮发送模拟答复和具体评审，保留失败、未验证及原历史身份。以下是待验证条件，不是通过记录。

## 主持与观察范围

共享字段资料承载直接候选、未知/冲突、部分答复、未知后的处置、额外风险选择、共用差异、各操作终点及跨模块流转。先实际评审具体流程，再按决定推进模块。安排写作或反馈中真实发现的局部缺口、实际模块收尾和后续受影响重开。角色/看板复用既有针对性自然资料，在同一runtime实际执行，或明确逐依赖不变的复用范围及原版本。

聊天、编辑MD和原生XMind反馈分别使用实际输入，业务变化形成候选后另给具体评审，回读同一准确MD。另实际发送独立控件/定位的纯技术反馈和现场表现与既有规则冲突的业务线索，分别观察责任分流、证据范围、有效决定保留与必要澄清。避免向执行角色提供本rubric或预填整场答复。

## 单MD与真实客户端证据

用户实际决定交接范围与用途后，fresh接收者只得到最新准确MD及其自己的引用。实际打开引用位置，恢复来源到分支、适用规则、真实决定、未决依赖、默认共用、交接与保留范围及下游职责。打不开的引用报告具体影响，不用未引用的旁侧记录补齐。带问题内容继续未知，下游P0核对和用户手动启动条件可恢复。

实际将受影响MD导入XMind客户端，观察中文、条件、问题区、说明区及必要层级。原生原件与另存编辑副本分开，实际文字/层级编辑保存回传，经reader读树后进入同一反馈分流与具体评审。记录实际客户端版本、输入/原件/回传身份、观察及处理过程。合成解析与真实客户端往返分别判断，未验证如实保留。

最终十二行表逐项提供通过、失败或未验证、runtime身份、具体文件/轮次及语义理由。静态一致性、模拟行为、native解析、真实客户端和真实业务分别报告。模拟不等于天津业务验收，不安装全局或自动启动下游。

# Q-R1：购买澄清（模拟开发验证）

执行来源：本票Agent实际读取新SKILL、roles-entitlements、feedback-review、review-and-progress及fixtures，按roles-request接续P-R1。这里没有新规划图/客户端证据。

客户是角色，普通/有效VIP是等级权益，有效/到期是状态，订单本人/他人是数据关系。默认购买模块→用户类型→功能，差异跨价格、结算和预约，值得独立用户分支；不新增管理员。页面只隐藏不是拒绝验证，PRD已给拒绝规则，故写操作拒绝检查但不声称执行。

生效和旧订单没有规则。两个独立问题一轮问：

1. VIP生效/到期按哪个时点？例如支付刚好在到期瞬间，A先留产品问题；B提供准确时区、时刻和包含关系；可自定义。推荐A，资料没有依据，不代选。
2. 旧未付单会员改变后怎么计价？例如80元旧单改价后支付，A保留产品问题；B按你提供的旧单规则写；可自定义。推荐A，不能拿新单规则覆盖旧单。

可继续范围：先评审两类当前明确的新单和订单/预约；到期旧单纳入但结果未决，或等产品再写。推荐先写明确部分，不使未知消失。尚无准确基线。

# #71 实际入口模拟执行过程

执行者：本票 Codex；所有“答复”均由执行者扮演用户自动生成，限定开发模拟，不是真实用户/产品决定。Root另行独立审查。原始资料为fixtures/maintenance-calculation-prd.md v1；不是结构化预填输出。实际读取入口及触发参考后逐轮书写。

## P1 接续前提与S1组织判断

只采用request中声明的模拟规划接续前提，无实际archify证据，不验证新规划绘图门。部门有真实新增/查询/改名，采用信息维护主线；“使用中”仅影响改名，作局部状态条件。费用受阈值与会员共同影响，采用计算主线、决策表/边界辅助。编号名称传入费用单，旧名称规则未明但与金额无依赖；不建审批/删除/完整生命周期目录。不按标题套全部模板。

模拟用户S1答复（对应P1与上述建议）：『就按部门操作主线、费用规则主线；使用中只补改名条件，不另开状态目录。历史费用单名称要保留问题，金额计算继续，不做删除审批。』适用范围：本模拟两模块，未知历史名称不清除；这是组织与范围决定，不是具体点评审。

## Q1 部门独立问题（展示q1）

1. 编号重复在哪个范围，大小写或空格算同一吗？如A01/a01。选全库原样比较、全库归一比较或按组织比较；推荐先明确归一口径，避免重复判断冲突，也可自定义。
2. 名称20按什么计数？20个ASCII与20个汉字是否一样？选Unicode码点、字节或自定义；推荐明确到计数单位而非直接用“20字符”生成边界。
3. 哪些部门可改名？选仅未使用、都可或其他；推荐按引用影响确认，不能根据当前页面推定。
4. 历史费用单名称跟改吗？选保留快照、展示新名或暂留产品问题；推荐暂留，因为资料没有结论。建议纳入关联核对，由你决定。

模拟用户A1（来源：执行者模拟角色，适用q1）：『编号全库原样比较，大小写不同是不同编号，不允许前后空格，格式其余先不扩；名称限1到20个Unicode码点，不做归一化，新增和改名相同。仅没有被费用单使用的部门能改名，已使用拒绝。历史单名称还没定，保留必需覆盖问题；先完成本模块其他点。查询精确匹配编号，找不到显示无记录。』

A1只明确上述规则，未回答历史名称，尚无准确MD。依赖名称口径和使用条件的具体边界/拒绝检查在A1后才写。

## R1 部门具体评审

实际展示并回读department-d1.md完整分支。模拟用户R1答复：『这个d1的新增、查询、改名检查通过，P1继续保留必需覆盖但预期未知。先更新这份内容，然后进入费用。』来源：执行者模拟；适用版本department-d1，全部部门检查；不批准尚未展示的费用点。现在可首次建立accurate.md v1，部门其他规则不因P1未答被阻塞。

## Q2 费用前置问题（展示q2）

1. “申请金额”具体是什么口径、币种和单位？如税前或税后、元或分；选优惠前原额/其他自定义，推荐明确比较基数，避免折后误判满额。
2. 输入精度及合法范围？如能否输入0或100.005；选到分/到厘/自定义。推荐明确业务可接受精度而非跟随显示位数。
3. “满100”含等于吗？选≥100或>100或其他；推荐先确认，不能由“满”字自行决定。
4. 会员优惠与减免能叠加吗？可选叠加、互斥或待产品；推荐先确认再问顺序，以免讨论不存在的组合。

模拟用户A2（执行者模拟，适用q2）：『人民币元，优惠前申请金额，输入非负到分，超过两位小数或负数拒绝。原额等于100就算满额，会员与满减可叠加。』尚未给顺序舍入，不输出确定会员结果。历史费用单名称仍未答。

## Q3 依赖问题（在A2明确叠加后，展示q3）

1. 叠加时先减10再九折，还是九折后减10？100元两种可能是81与80。选这两种或自定义，推荐让产品明确，Agent不代选。
2. 中间值和最终结果如何舍入、在哪一步？如100.05减10再九折有81.045。选仅最后四舍五入到分、每步舍入或其他；推荐明确中间保留与最终模式，不能用语言运行时默认。

模拟用户A3（执行者模拟，适用q3）：『先判断原额满额，满额先减10，再对会员打九折；不满额会员仍九折。中间不舍入，只在末尾十进制四舍五入到分。非会员不打折。零金额就是零，不另设封顶，其他币种不支持。这些明确项都写点；历史名称依然待定。』本轮规则明确仍不构成具体点评审。

## R2 费用具体评审与拒绝

实际展示并回读calculation-d1.md。模拟用户R2答复（执行者模拟，适用费用d1）：『这个版本先不通过。请再用一个恰好第三位是5的合法输入算例把末尾四舍五入写实，比如100.05，避免只看100.01发现不了舍入方式不同。部门已通过部分不用动。』

该反馈要求把已明确规则落实为更有区分力的具体点，没有新业务规则。准确MD保持v1。将费用会员完整分支重现为d2，增加100.05→81.045→81.05；d1和答复保留。该值可区分ROUND_HALF_EVEN的81.04，也可区分先九折再减10的80.05；不以只写“按规则舍入”代替检查。

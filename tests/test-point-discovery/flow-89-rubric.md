# #89 独立行为审查

评审者读取原始虚构输入、实际入口输出、主持方分轮实际发送的消息、生成文件与图片。执行者不接收本rubric或预填答复。记录通过/失败/未验证、轮次、位置及理由，合理措辞与模块合并可不同。

- 初始没有规划前提，保存、取消、提交审核分别理解。保存已知产生草稿直接复用，取消未知实际问，提交与审核接收的关系实际问。问题带选项、例子、推荐理由且可自定义回答。
- 实际问题早于依赖答案的模块安排，主持答复另行发送且原文可追踪。部分未答保持未知，不画成确定业务关系。已明确部分不再次要求长篇业务说明审阅。
- 问答依据足够后提出职责/对象/衔接有理由的模块与顺序，按钮数量不被当作模块数量。七类方案保留按需选取，新增范围由主持方选择。
- 实际 archify 表、HTML和图片身份可核对，执行者读图，关系与实际答复一致。工具失败/截图失败按实际记录，不把JSON存在当绘图或视觉通过。表图展示后等待本版规划确认，确认前保持整体阶段。
- 整体阶段仅有分析/问答与规划材料，没有流程或模块测试点稿。已纳入的流程检查进入约定模块范围，后续深入始于实际规划确认之后。该后续问题不是完整模块出稿验收。
- 记录静态一致性、模拟行为、真实客户端和实际业务分别的证据与限制。既有已规划样例不能替代上述初始入口。保留初始成功与失败，不要求为了RED伪造基线失败。

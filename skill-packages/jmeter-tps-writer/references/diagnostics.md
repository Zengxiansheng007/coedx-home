# 失败诊断与复验

先读取本轮摘要和分轮 JTL，按账号编号、目标、HTTP 状态、耗时和脱敏响应类型定位样本。在本机把该目标原始 cURL 的方法、路径、有序查询、正文编码、业务头与 JMX 对照，检查同轮引擎日志中的启动错误、异常及结束状态。日志、原请求及账号文件留在本地。已定位生成错误时修正生成器，在新输出目录复跑并保留原轮。

HTTP 200 且仅返回数值 code=0 时，在对话展示已观察到的字段、默认断言与建议规则。先取得接口负责人对该目标的明确确认，再为该目标增加 --confirmed-code-zero T01 参数，在新目录复验。字符串 "0" 不满足数值条件。保留原目标顺序，变更输入后重新核对编号。

普通业务失败不能推出缺查询令牌。相同症状复现且没有新证据时停止重复试跑。在聊天正文按目标列出实际、预期、已排查项，一次列出仍需确认的独立问题（例如成功字段的类型和值、登录失效提示或接口令牌要求）。中断时给出已记录样本、明确未启动的阶段与没有最终样本的未知组合。

按原编号传入 --diagnose-target T02 时，只发送该目标。使用 --requests 会先原样复验该目标，再用整理后的计划复验它。使用 --plan 会直接复验该目标。两种入口均在独立输出目录保存 result/diagnostic.jtl。成功后使用该目录中的完整 plan.jmx，从 --plan 入口不带 --diagnose-target 进行完整验证。原样和整理后样本的 wire_method、wire_cookie、wire_ctoken 分别记录实际方法及 Cookie、URL ctoken 的有无，可与最近通过轮逐项对照。

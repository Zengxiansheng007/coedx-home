# 按完整来源归属公共前置

编写者先读完整原材料，标出角色、起点、执行时机、触发动作、输入含义、证据对象与各例最后检查。对每项准备列全同模块每例的归属。全体明确的起点、部分用例因后续取证而明确需要的准备，可按来源直接写成待评审稿。这里的根据是材料中可指认的陈述和业务动作，无需虚构范围评审答复、也不授予执行或最终批准。只有文本重复、或旧准备与当前终点关系未明时，把原文留在原例，注明待核原因。将个例独有的角色条件、资格、素材、状态继续留在该例，公共后置仅来自实际材料。按每例执行、同一有效环境可沿用、失效重核等频次分别写明。

1. 从手写材料开始时按 [handwritten-input.md](handwritten-input.md) 逐条调用 `build_handwritten_batch` 或作者 CLI。将所有完整用例、数据、选择、来源与问题合为同一批，保持原 ID、来源行号、输入、特殊前置、判据和终点。单独陈述共同角色和共同起点；若起点另有个例限制，将该限制写为本例特殊前置。把有待核对的旧准备独立保存在原例的 common_preconditions，采用其完整原文。
2. 为模块编写 UTF-8 JSON 数组。每项包括 `module_path`（完整目录）、`name`、`instruction`（准备的对象和动作）、`timing`、`source`（文件与行/段）、`applicable`、`pending`、`excluded` 三个对象。逐一覆盖同模块全部 ID，三组互斥。`applicable` 的每个值是本例原始准备步骤 ID 的数组，也可使用 `context/role`、`context/initial_state` 分别表示整个角色或整个初态字段。只有公共说明完整涵盖该字段时才选择它。任何在共同准备步骤和角色/初态两处表达的相同义务须把对应来源都纳入同一项，避免重复。特殊条件放在原例。其他两组按 ID 写待核原因或已确定不适用的来源理由。每项至少一个适用者；整项待核时直接保留原准备。所需频次、关联本次执行或具体条件写入 instruction 与 timing。
3. 使用实际入口生成两个稿件。将下例路径换为实际输入与未使用的输出目录。第二次传入带已核适用映射的完整候选，可多次指定 `--case`，保持要求的选取顺序。

```text
python -B scripts/source_preparation.py --candidate full.json --assessment assessment.json --output-dir full-review
python -B scripts/source_preparation.py --candidate full-review/candidate.json --case CASE-A --case CASE-B --output-dir excerpt
```

交付每个输出目录的 xmind.md。输出 candidate.json 保存完整同版来源；节选范围以 xmind.md 的用例为准。核实模块只出现一次公共前置，节选只包含本次所选的实际适用项。逐例对照独有准备、待核原文、取证对象以及最后业务检查；出现错误时修正全量归属并重新输出。独立验证保留原材料 SHA-256、技能版本、实际调用、两份稿件、逐例归属和仍待核的条件。

## 公共操作、数据与取证

使用同一份完整归属数组。环境与初态沿用上文的前置格式。对有来源的具名固定动作设置 `kind: operation`，数据生成和素材约定用 `data`，定位证据的方法用 `evidence`。这些条目的 applicable 按用例编号列出一个或多个 `steps/<本例完整步骤 ID>`；数据约定还可定位 `data/<本例实际引用的数据 ID>`。一个步骤可同时使用数据和证据约定。只把在同一语境具有相同业务含义的动作归为同一公共操作。多次触发时逐次绑定，保留每次调用的对象。本例步骤的操作文字和公共 instruction 完全一致时可显示操作名，其余步骤仍显示自身的触发动作。公共定义写在模块下，各例保留原始数据、每步判据及终点。

逐项写清执行时机和失效条件。可沿用的环境地址写明换环境或失效后重核；本次执行标识逐例重新取得。共用提交动作须读取本例当前这一次调用的输入，区分省略、空字符串和空对象。复用同规格素材前核实其规格；材料要求现场采集、计时或开始回执时须取得本次素材、时间或回执。定位同次证据的方法可写在模块；证明没有副作用时写明窗口何时开始和结束。字段、实收对象、值或无记录的成败条件留在相应用例。来源没有声明清理时不增加公共后置。

公共定义业务含义改变前，使用原评审稿的完整候选版本、模块路径和名称取出所有实际引用者。每级目录分别传一次 `--module-path`：

```text
python -B scripts/source_preparation.py --candidate full-review/candidate.json --impact 登记订单 --module-path 业务 --module-path 订单 --version <候选完整版本> --output-dir affected-review
```

逐一复核 affected-review/xmind.md 中的用例，记录哪些仍适用、哪些保留本例做法及原因。用完整归属数组保留例外和未受影响的条目，再用原候选和更新后的 assessment 输出到新的目录。保留原版本和各例原有评审、执行状态。只看某次节选的人应从这个完整版本定位影响。

整批导出标明完整候选范围，节选标明本轮范围。两种评审稿都把测试点放在用例首项。有明确测试点时沿用原文，其余采用本例业务标题。复制评审稿时一并保留同级的配套文档目录及相对位置。

# 人工从同版 P0 复制调用输入

先完成目标用例的真实输入、操作、逐步预期与终点。阅读原始业务材料，对每个输入框分别判断是否有适用的同版 P0 调用。比较来源、业务用途、输入框、调用时机和目标对象。错误分支也可以复制正常调用的输入，随后直接核对它自己的报错与终点。共同操作段按 [step-reuse.md](step-reuse.md) 单独评估。缺少合适基准的调用保留完整输入。

运行 `scripts/source_preparation.py --candidate candidate.json --input-assessments inputs.json --output-dir OUTPUT`。已有范围副本按需传 `--source-catalog` 指向其完整同版父稿。可重复传 `--case` 指定展示范围。首次评估及重新评估使用同一入口，后续从保存的候选直接生成。

评估 JSON 用目标用例编号作为键，每个值是调用列表。每行包含以下内容。

- `step_id`、`data_id` 指向本例业务步骤及该步使用的完整 JSON 输入。
- `p0_case_id`、`p0_step_id`、`p0_data_id` 指向同版 P0 的一次调用与具体输入框。
- `source_basis` 记录材料出处以及此次输入可以复用的业务理由。
- 若用例测试点依赖某个应当保持原值的键，`focus_paths` 可列出对应键路径，每条路径用 JSON 字符串数组表示。键含点时仍为单个键。变更和保留的值从当前两份来源读取。

传入某例的完整列表会替换该例之前的输入评估。空列表撤销该例的引用。读取者复制所指的 P0 输入，再按每项提示改值、增加或删除键。数组作为完整有序值替换。按相同运行值比较对象结构、键、类型和值；显式空字符串、空对象、null 和省略分别核对。绑定的调用用途变化或父稿不符时复核来源，保留本例输入。

编写中或合入前只评部分用例时，按该条引用找到同版 P0 的步骤和输入框。正文已有这块 JSON 就原处复制。正文没有时，在文末「供复制」取完整输入；引用同一次调用的多例共用一块。不同步骤即使用相同输入也分别列出。附录只用于复制，待评清单和 Agent 文件按实际选中的用例取数。

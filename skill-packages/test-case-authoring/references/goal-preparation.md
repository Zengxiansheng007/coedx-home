# Preparation and verification goals

Read before first generation, modification, shared-operation extraction or recovery.
This is agent interpretation of sources, not a keyword classifier. Use the existing
candidate, source coverage and sole Q&A; no parallel decision ledger is required.

## Decide ownership before writing steps

1. Read the complete source, effective answers and current case goal/endpoint.
   For each proposed action identify its purpose, source and downstream consumer.
   Establishing a required state belongs to preparation; checking the feature under
   test belongs to its case steps. An observable preparation outcome proves only
   readiness, not that the business goal passed. Names, dates and field keywords
   never decide ownership.
   沿当前目标逐动作检查建立的状态及后续消费者；即使同样是新增、切换或读取，
   在一个用例可能是准备，在另一个用例可能就是被测目标。准备边界由进入目标所需
   状态决定，不按来源编号、固定前几步或整个批次统一切分。
2. Split a mixed action at its meaningful boundary. Retain necessary page entry,
   authentication, conditions and data. Remove a measurement from unrelated cases
   only after checking that no later action, expected result or data formula consumes
   it. Keep omitted source content accounted for with its actual independent owner;
   source coverage is not permission to discard a dependency.
3. Before proposing a new independent goal, inspect the existing full catalog and
   coverage by business object, state, trigger and result. Improve a matching case
   under its existing identity; a title match alone is insufficient. If the catalog
   is unavailable, retain a possible-duplicate question. Do not modify an out-of-scope
   case or the original P0 merely because a related goal was found.
4. Attach a measurement to the consumer in the current case at the required position.
   Specify how this invocation obtains the current value and compares the business
   outcome. A previously captured value from another case is not current evidence.
   Re-entry or invalidation refreshes the value when its source requires it.
5. Preserve source-confirmed timezones, defaults, validity, reuse and invalidation.
   Recording a value is evidence collection, not an expected functional result.
   For a time-default goal, state the sourced default and observable comparison;
   display precision, tolerances or waits without evidence remain questions. A
   missing precision rule blocks only comparisons depending on that precision;
   independent controls and known requirements continue. Do not invent replies.
6. Recheck the classification after feedback, dependency changes and resumed work.
   Use existing candidate/feedback APIs and the current sources, retaining unshown
   content and approvals only for unchanged versions. Complete the same check before
   calling public render/save entries; renderers cannot repair semantic ownership.

## Drafting checklist

Use this checklist while preparing an interpretation or design; it is not another
required file or a schema. Record useful rationale in existing source coverage,
provenance, questions or the current task evidence:

| Check | Required evidence |
| --- | --- |
| Goal and endpoint | Source and effective answer; existing matching case or unresolved search |
| Preparation | State established and the goal that needs it |
| Independent check | Action, actual data consumer, business expectation and observable comparison |
| Dynamic value | Current acquisition point, lifetime, refresh condition and consuming step |
| Unresolved detail | Exact missing rule and only the dependent comparison/cases |
| Readback | Candidate and readable view retain entry, order, references and lifecycle |

Definition reuse changes presentation only: long-lived, validity-limited and
per-case instances keep their confirmed frequency. Shared wording never means
one execution for the batch. The authoring skill describes these conditions;
execution remains a separate authorized workflow.

## Synthetic contrast

A stock form's category-default check needs entry into a fresh form. A balance
capture used only to verify reservation arithmetic belongs to the independent
reservation case; it does not become preparation for category-default checks.
That reservation case captures its own current balance before reserving and
compares the result with the source-defined quantity rule. Conversely, if a
source requires a current exchange rate to price this very order, keep acquisition
at its actual dependency position even when another case tests rate display.
These examples supply no real product rules.

## Validation boundary

Exercise authored material through existing conversion/design, rendering and
save/readback entries. Check exact actions, expectations, dependencies and pending
questions, plus a non-time cross-business counterexample. These checks prove
structural preservation of supplied meaning. Separately run a fresh-context Skill
prompt to assess actual interpretation. Neither evidence is user approval,
XMind client acceptance, P0 qualification or business execution.

# 恢复接入与兼容性

扩展版本 1.0.0。这是 Agent 的维护说明；不提供自动更新工具，不下载或替换上游。

## 资产与替换边界

- 模块入口是本目录中的 [extension.md](extension.md)，同目录保留 [record.md](record.md) 和本文件。
- 技能入口是 [SKILL.md](../../SKILL.md)。安装或更新时复制整个 `grill-with-docs` 目录。若换用了缺少扩展的上游版本，从原分发版本恢复三个文件，再核对入口引用。
- `extension.md`、`record.md` 为运行依赖；本文件为升级维护依赖。没有对旧定制引用文件的隐藏依赖。临时表属于目标项目中的会话记录，清理不会修改上述模块文件。

## 唯一接入块

在 SKILL.md 的 YAML frontmatter 之后、首个执行步骤之前放置以下一块。相对链接以 SKILL.md 所在目录解析；若部署布局改变，重新计算并实际打开核对。

```markdown
<!-- grill-coverage:integration:start -->
在首次提问或恢复访谈前，必须读取并应用[覆盖扩展](references/grill-with-docs-coverage/extension.md)及其必需引用，贯穿逐轮答复、汇总复核、文档审阅和确认清理。扩展在这些阶段的记录与完成条件优先于本技能及辅助技能的宽松收尾规则。文件缺失或流程冲突时，先按[恢复接入与兼容性](references/grill-with-docs-coverage/reintegrate.md)修复，恢复前报告具体阻塞。
<!-- grill-coverage:integration:end -->
```

只有一处接入是因为它在所有执行步骤之前加载，且明确持续适用阶段；正文规则在扩展内维护。模块入口本身缺失时，检查预期同目录的本接入说明；整目录不可读时报告实际缺失路径，不能声称已加载。

## Agent 更新后操作

1. 读取用户指定的实际新版 SKILL.md、它要求的辅助入口及本模块。先明确本次替换目录和待写文件；保存必要的原入口比较基线，保留无关修改、元数据和调用策略。
2. 对照下表检查文件可达性与阶段语义。失效的历史自定义引用若被新版移除，本扩展不依赖它们；新版仍声明的必需依赖缺失时，说明受影响功能并修复后继续。不要默默忽略整个上游的加载错误。
3. 搜索接入标记及同目标链接：无块则插入，有且正确则保持；过时块就地修正；重复块合并成一块，保留无关内容。若文件语义变化导致单块不能接入，先分析冲突再做最薄适配，记录必要变动。不能靠重复粘贴规则掩盖冲突。
4. 重新读取实际入口并打开全部必需引用，核对扩展版本、路径和优先级。验证第二次恢复不会新增引用。检查结果区分文件存在、结构通过、行为通过和未验证。
5. 使用隔离目录模拟替换，并在新上下文中从实际入口开始执行下列场景。只给入口路径、原始场景和必要资料；让执行者自行沿引用加载，避免把扩展正文或预期结果塞进提示词。旧对话复述和字符串检查不能代替此项。没有新上下文执行能力时记录未验证，不宣称行为兼容已通过。

## 必需契约与责任

| 契约 | 提供方 | 更新后核对 |
| --- | --- | --- |
| 覆盖表、轮后扩展、汇总门、恢复、确认清理 | 本模块 extension.md | 各阶段可执行，空 frontier 不越过未决前提 |
| 单份 MD、真实答复与历史、永久决定、版本确认记录 | 本模块 record.md | 使用实际文件，永久内容不随表清理 |
| 决策树/frontier 与问题选项、推荐、理由、例子 | 本模块给出必需规则，上游可提供更丰富的访谈辅助 | 新版的单题/批次方式或结束条件冲突时，仅在此扩展范围按模块契约适配 |
| 按需事实研究 | 上游的研究流程及宿主可用工具 | 缺失事实/工具保留阻塞；不能默认事实已解决 |
| 需求文档生成和交付 | 上游负责专业文档，本模块提供延后写入、版本确认的必需边界 | 若上游提前改文档或无版本审阅阶段，接入优先级须生效；若无文档能力则需适配 |
| 术语、ADR、调度回流与下一路线 | 上游及当前调用方 | 按当前实际模式使用；本模块不迁移这些历史定制 |

若新版完全取消交互、跳过真实答复、自动完成或禁止所需持久化，应报告具体阶段冲突并在授权范围适配后重验。上游强制前置依赖缺失也会阻塞，扩展文件存在并不能豁免。

## 最小验证场景

- 输入包含尚未形成问题的原始要求，以及资料已回答的事项。观察遗漏主题被跟踪、已有事实被复用。
- 回复只覆盖部分问题，并追加新条件。观察剩余项、新分支与依赖排序，未答保持未决。
- 暂无可问问题但事实/依赖未解决。观察查证或阻塞；最终汇总要有可追溯范围处置。
- 新上下文只拿到访谈记录及其资料引用。观察恢复位置、未决前提、真实答复与有效决定复用。
- 汇总确认而文档仍待审时保留表；当前文档版本得到明确确认后，观察永久确认先保存、精确清理及回读；再次恢复应能辨认已清理。
- 审阅中和清理后的变更只重开受影响分支；保存失败、清理中断时保留实际状态。通过新版本确认后清理，历史问答和模块文件保持完整。
- 缺失必需文件、加载引用重复、上游提前结束的变体暴露明确问题；修复后重复接入保持单块，再运行受影响场景。

将实际输入、回复承接、文件前后变化和限制留在隔离验证产物中。测试答复只属于测试，不作真实业务确认；可保留测试用的清理前后快照以验证不误删，真实访谈不归档临时表。

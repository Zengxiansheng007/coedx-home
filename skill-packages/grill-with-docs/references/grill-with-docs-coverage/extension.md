# grill-with-docs 覆盖扩展

版本：1.0.0。作用域：通过 grill-with-docs 开展的需求访谈，包括恢复、审阅补问和确认后的变更。此文件是普通参考模块，由入口显式加载。

首次使用或恢复时，连同 [单份记录契约](record.md) 一起读取。更新上游或发现缺失文件、流程冲突时，读取 [恢复接入与兼容性](reintegrate.md)。本模块负责覆盖、记录和确认清理；上游继续负责专业访谈、术语、研究及调用方回流。

## 1. 建立覆盖范围

首次提问前，读取用户原始要求及相关资料，在目标项目同一份访谈 Markdown 中建立覆盖与分支表。已有同主题记录时先恢复它；已确认且依据未变的决定直接引用。

逐项核对原始要求的去向，再按实际相关性走查角色、正常路径、异常与边界、前后环节依赖、验收方式。记录尚未检查或尚未转成问题的主题；检查维度按任务裁剪，不把通用清单自动升级为新增需求。新范围由用户决定。

表中每行有稳定 B 编号、主题、来源、前置依赖、状态、问题或决定依据、下一步。状态使用：未检查、待查事实、待提问、等待前提、已解决、已延期、已排除、不适用。后四项为可关闭状态：已解决须有实际资料或答复依据；延期、排除须有用户明确决定；不适用须说明与当前范围或事实的关系，不能用来隐藏未答问题。资料事实与用户业务选择分开。

## 2. 每轮推进

1. 先保存用户实际答复及来源；保留答复历史，区分推荐、推断和未回复。
2. 检查是否只答了一部分、引出新条件或例外、改变原决定依据、产生事实缺口或依赖。拆分剩余问题和新增分支，关联原 Q/B 编号；受影响的已解决分支重新打开。
3. 更新覆盖表，再计算 frontier：前提明确且尚需用户决定的所有相互独立问题。每题给出选项、推荐、对应项目约束的理由和简短具体例子；依赖同轮未答问题的提问留到后续。
4. 先保存本轮问题再发送，等待实际答复。用户一条答复覆盖多题时引用同一来源；含糊的“可以”只绑定其明确指向的内容。

事实缺口先查已有资料，再使用上游可用的研究能力。只挂起依赖该事实的分支，其他独立问题继续。工具不可用或事实无法查明时记录具体阻塞及下一步；用户能决定的范围调整可提问。frontier 为空只表示此刻无可问决策，并不代表未检查、待查事实或等待前提的分支已关闭。依赖循环须拆解前提或请求必要决定。

每轮保存后核对实际文件。写入失败时说明待保存内容和恢复位置，处理持久化问题后再推进；聊天记忆不能代替已保存记录。

## 3. 汇总前复核

回读原始输入、资料引用和答复历史，而非只遍历已提出的问题：

- 每项原始要求、当前范围内的相关场景和依赖都有去向；发现遗漏主题即补入表并处理。
- 部分答复、矛盾、失效依据和影响需求的假设都有明确处置；相关分支均达到有依据的可关闭状态。
- 仍待查事实、等待前提或等待答复时继续查证、补问或报告阻塞。用户明确延期、排除或改变范围后，重新检查剩余范围。

记录简短复核结论：覆盖了什么、哪些延期或排除及其实际依据、剩余限制。将需长期保留的范围决定写入永久问答或最终决定区，不能仅存在临时 B 行中。汇总最终决定及待更新文档，等待用户确认理解一致；已有对完全相同内容的明确确认可复用。

## 4. 文档审阅与清理

访谈期间只维护访谈记录及必要研究证据。汇总得到确认后才统一创建或修改目标需求文档，保存可审阅版本并交给用户。汇总确认与该文档当前版本确认分别记录。只依据用户已审阅的实际版本确认，不把沉默、推荐或先前方案确认当作后来新增文档内容的确认。

文档待审、暂停、阻塞以及只有汇总确认时保留临时表。用户确认实际需求文档当前版本后，按以下顺序完成：

1. 将版本、路径、真实确认来源和最终决定保存到临时区之外；检查延期、排除、不适用的必要理由也能在永久内容中定位。
2. 读取实际文件，确认问题、实际答复及历史、最终决定、汇总确认和版本确认均已保存。只删除本访谈的覆盖与分支临时区，保持其他内容不变。不另行归档临时表或复制到需求正文；长期扩展模块保留。
3. 回读核对临时区已删除且上述永久内容完整，再记录清理完成。中断或失败时记录实际进度；恢复后检查已保存确认及文件状态，继续未完成步骤，不伪报清理成功。

审阅出现实质变更时，在仍保留的表中打开受影响分支，先补问，再按确认结果修订。清理后出现变更时，从当前需求和永久问答重建受影响范围的临时表，B/Q 编号保持唯一且不复用；复用未变决定。确认绑定新版本及受影响内容，随后再次清理。排版、错别字按上游规则处理。

完成条件：覆盖复核通过、问答及汇总确认可追溯、目标文档当前版本得到实际确认、临时区清理经回读验证，以及上游适用的交付/回流条件满足。确认等待或环境阻塞如实报告。本机制提供已识别分支的可追踪性，不能保证所有可能问题都被发现。
